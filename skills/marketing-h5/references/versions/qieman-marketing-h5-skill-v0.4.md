# 且慢营销 H5 Design Skill

> Version: V0.4  
> 适用于且慢 App 内营销 H5、策略介绍页、活动页、权益页、定投页、诊断页、报告页、功能上线页、内容专题页等移动端页面。  
> 目标：把真实业务中的营销页面沉淀成一套 **页面框架 + 视觉规范 + Pattern Library + 生成检查清单**。

---

## 1. Skill Overview

### 1.1 适用范围

本 Skill 适用于：

- 且慢 App 内营销 H5
- 策略介绍页
- 活动营销页
- 优惠券 / 福利页
- 节假日活动页
- 定投教育 / 定投活动页
- 账户诊断 / 持仓分析页
- 权益 / 会员页
- 新手指南 / App 使用指南
- AI / 产品功能上线页
- 市场解读 / 投教专题页
- 年度账单 / 半年度报告页
- 基金品类投资指南页
- 服务信任 / 品牌陪伴页

### 1.2 不适用范围

不适用于：

- PC 官网整站
- 后台管理系统
- 纯交易表单页
- 复杂数据分析看板
- PPT / Keynote 报告页
- 非且慢品牌视觉页面

### 1.3 与 qieman-ui-design 的关系

- `qieman-ui-design` 负责基础 UI 规范：颜色、字体、按钮、卡片、App 容器、常规交互。
- 本 Skill 负责营销 H5 的页面逻辑、内容框架、视觉氛围、转化路径与营销 Pattern。
- 生成营销 H5 时，应先遵守 `qieman-ui-design`，再叠加本 Skill 的营销页面规范。

## 2. Core Brand Principles

### 2.1 金融可信

营销页必须建立信任感，而不是单纯制造刺激感。

要求：

- 收益、回撤、胜率等数据必须有来源和口径。
- 不得承诺收益、保本、稳赚。
- 风险提示必须保留且可读。
- 图表和数据必须克制、清楚、移动端可读。

### 2.2 克制轻盈

且慢营销页可以有活动感，但不能电商化。

避免：

- 大红大金
- 红包雨
- 夸张金币堆叠
- 强刺激促销语
- “错过血亏”“稳赚不赔”等焦虑表达

### 2.3 用户陪伴

页面语气应像专业顾问陪伴用户理解问题。

推荐：

- 安抚而不煽动
- 专业但不生硬
- 有解释感
- 有长期主义
- 有行动引导

### 2.4 数据清晰

所有图表、表格和数据卡必须服务一个明确结论。

要求：

- 每张图只表达一个核心观点。
- 数据卡不堆满指标。
- 图表下方必须有数据来源、统计时间或说明。
- 复杂内容应被拆成卡片、步骤或图示。

### 2.5 移动优先

所有页面默认在且慢 App WebView 中阅读。

- 设计基准宽度：375px
- 高度不限
- 单列纵向阅读
- 禁止横向滚动
- 内容卡默认宽度：343px
- 左右安全边距：16px

## 3. App H5 Canvas Rules

### 3.1 页面容器

```css
html,
body {
  margin: 0;
  width: 100%;
  min-height: 100%;
  overflow-x: hidden;
  font-family: "PingFang SC", "MiSans", system-ui, -apple-system, sans-serif;
  color: #333333;
}

body {
  display: flex;
  justify-content: center;
  background: #E8F1FE;
}

.phone,
.page {
  width: 100%;
  max-width: 375px;
  min-height: 100vh;
  margin: 0 auto;
  overflow: hidden;
  background: var(--surface-page, #ECF4FF);
  position: relative;
}
```

### 3.2 App Shell 强约束

- 顶部导航、内容区、底部 CTA 必须属于同一个 375px 容器。
- 不允许导航栏全浏览器宽度、内容区 375px 的割裂结构。
- 不允许 PC 布局混入 App H5。
- 页面可以在浏览器中居中显示，但 App 页面主体必须完整。

推荐结构：

```html
<body>
  <main class="phone">
    <header class="statusbar"></header>
    <nav class="topnav"></nav>
    <section class="hero"></section>
    <div class="content"></div>
    <section class="risk"></section>
    <footer class="fixed-cta"></footer>
  </main>
</body>
```

### 3.3 内容宽度

- 页面容器：375px
- 内容卡片：343px
- 页面左右边距：16px
- 内容卡高度：不限制，按内容自适应
- 风险提示可使用 343px 内容宽度，也可作为正文底部弱化文本区

## 4. Marketing Page Design Framework

### 4.1 Page Type First

生成营销 H5 前，必须先识别页面类型，并选择对应 Pattern。  
不得在未判断页面类型的情况下直接生成通用营销页。

必须判断：

- 页面是策略介绍、活动页、功能上线、定投教育、诊断转化、权益说明、报告复盘，还是投教专题？
- 页面唯一主目标是什么？
- 用户当前处于什么情境？
- 页面最终希望用户做什么？

### 4.2 One Page, One Main Goal

每个页面只能有一个主目标。

示例：

- 优惠券页：领取 / 使用优惠券
- 诊断页：添加顾问开启分析
- 定投页：开启定投
- 功能上线页：体验新功能
- 报告页：建立信任并继续持有
- 权益页：去达标 / 去领取权益

### 4.3 Scene → Value → Proof → Action

营销页通用递进链路：

```txt
场景切入
→ 用户问题 / 机会
→ 解决方案
→ 价值证明
→ 操作路径
→ 行动按钮
→ 风险提示
```

不同 Pattern 可以变化顺序，但不得缺少理解路径。

### 4.4 One Screen, One Key Message

移动端每一屏只表达一个核心观点。

要求：

- 一张卡片只表达一个核心信息。
- 长段落必须拆成短段、列表、图表或步骤。
- 不要在一个模块内同时讲背景、规则、收益、操作、风险。

### 4.5 User Journey First

先设计用户理解路径，不直接堆内容。

必须回答：

1. 用户为什么要看？
2. 用户当前遇到什么问题？
3. 且慢提供什么解决方式？
4. 为什么这个方式可信？
5. 用户下一步该做什么？
6. 风险与规则是什么？

### 4.6 Visual Trust over Promotion

且慢营销页优先建立信任感，不做强刺激促销。

可以有：

- 轻活动感
- 情绪承接
- 福利点
- 节日氛围
- 成就感
- 陪伴感

但不能做成：

- 电商大促页
- 红包抽奖页
- 暴富暗示页
- 夸张收益承诺页

### 4.7 Data Must Have Context

所有收益、回撤、胜率、用户占比、历史表现必须有来源和口径。

要求：

- 数据来源
- 统计时间
- 历史测算 / 实盘说明
- 不代表未来表现说明
- 必要时补充适当性说明

### 4.8 CTA Must Match Page Goal

CTA 必须与页面主目标一致。

推荐：

- 去领取
- 去充值
- 去定投
- 去看看
- 开启信号定投
- 添加顾问开启分析
- 体验智能转换
- 开启转托管

避免：

- 泛泛写“立即购买”
- 一个页面多个同权重 CTA
- CTA 与页面内容无关

### 4.9 Risk Disclosure Always Visible

风险提示必须保留且可读，不得隐藏到不可见位置。

## 4.10 Marketing H5 Structural Skeleton

且慢营销 H5 默认采用：

```txt
Hero 主题氛围区
↓
Content 主内容卡片区
↓
Risk Disclosure 风险提示区
↓
Bottom CTA 底部行动区
```

### 4.10.1 Hero 主题氛围区

Hero 用于承接主题、建立情绪、突出主利益点。

默认规则：

- 宽度：375px
- 推荐高度：320px–420px，常规约 400px
- 包含页面标题、副标题、主视觉、核心标签或关键权益
- Hero 不能过高，避免挤压首屏关键信息
- Hero 与下方内容区必须自然过渡，不能硬切

### 4.10.2 Content 主内容区

主内容区默认采用居中的卡片承载信息。

规则：

- 内容卡宽度：343px
- 左右边距：16px
- 卡片高度不限
- 卡片之间需保持稳定垂直间距
- 主内容区采用单列纵向阅读流

常见卡片：

- 数据卡
- 说明卡
- 图表卡
- 步骤卡
- 权益卡
- 策略卡
- 顾问服务卡
- 活动规则卡

### 4.10.3 Content Stacking Rules

- 每个模块独立成卡。
- 一张卡只表达一个核心信息。
- 内容按“背景 / 价值 / 证明 / 操作 / 承接”递进。
- 长文必须拆卡，不直接堆成长段落。

### 4.10.4 Risk Disclosure Placement

风险提示应位于主要内容之后、底部 CTA 之前或页面底部区域中。

要求：

- 与主内容视觉层级拉开。
- 可采用纯文本区，不强制白卡。
- 字号应保证可读。
- 不得折叠、隐藏或弱化到不可阅读。

### 4.10.5 Bottom CTA

页面底部应设置清晰主 CTA。

要求：

- 按钮居中。
- 使用且慢品牌蓝。
- 文案表达明确动作。
- CTA 与页面唯一主目标一致。
- 次级 CTA 不应抢主 CTA 权重。

### 4.10.6 Layout Type A / Type B

#### A. 首屏氛围图 + 下方卡片流

适合：

- 策略介绍页
- 活动营销页
- 优惠券页
- 假期收益页
- 功能上线页

结构：

```txt
Hero 氛围区（约 375×400）
↓
343px 卡片流
↓
风险提示
↓
CTA
```

#### B. 长内容专题 / 长文解释页

适合：

- 服务信任页
- 市场解读页
- 品类指南页
- 年度报告页
- 复盘页

结构：

```txt
简化 Hero / 标题区
↓
长内容卡片流
↓
图表 / 案例 / 说明块
↓
风险提示 / 数据口径
↓
CTA（可弱化）
```

### 4.10.7 Structural Priority Rule

页面结构优先级高于装饰表现。

先确定：

- Hero 区
- 内容卡片区
- 风险提示区
- CTA 区

再决定插画、颜色、图标和图表。  
不得只追求局部视觉效果而破坏整体阅读结构。

## 5. Base Information Architecture

### 5.1 Hero 首屏

Hero 应快速回答：

- 这是什么页面？
- 和我有什么关系？
- 我为什么要继续看？

Hero 常见内容：

- 主题 / 场景 / 主利益点
- 一句话价值主张
- 主视觉
- 首屏关键数据或关键权益

### 5.2 Context 背景说明

用于解释用户为什么需要关注。

可包含：

- 市场背景
- 活动背景
- 用户痛点
- 机会窗口
- 政策 / 节假日 / 额度变化

### 5.3 Core Value 核心价值

根据页面类型表达：

- 策略价值
- 产品价值
- 权益价值
- 功能价值
- 服务价值
- 配置价值

### 5.4 Evidence 证明模块

可使用：

- 数据
- 案例
- 图表
- 对比
- 历史验证
- 用户行为
- 主理人动作
- 服务记录

### 5.5 How-to 操作路径

用于降低行动门槛。

可包含：

- 领取方式
- 使用步骤
- 开通流程
- 定投方式
- 联系顾问
- 操作截图
- 时间轴 / 步骤流

### 5.6 Product / Service Carrying 承接模块

可承接到：

- 策略卡
- 产品卡
- 顾问服务
- 活动入口
- AI / 功能入口
- 配置专区
- 会员权益

### 5.7 CTA 行动转化

CTA 类型：

- 主按钮
- 次按钮
- 固定底部按钮
- 模块内按钮

CTA 必须与页面主目标一致。

### 5.8 Risk / Rules 风险与规则

必须根据页面类型补充：

- 投资风险
- 活动规则
- 数据口径
- 适当性说明
- 功能规则
- 优惠券限制
- 统计方法

## 6. Visual Design Framework

## 6.1 Color System for Marketing H5

且慢营销 H5 的配色公式：

```txt
Soft Atmosphere Background
+ White Content Cards
+ Brand Blue CTA
+ Warm Accent for Benefits
+ Low-saturation Financial Illustrations
```

也就是：

```txt
浅色氛围底
+ 白卡内容层
+ 蓝色行动按钮
+ 暖色利益点
+ 低饱和金融插画
```

### 6.1.1 Primary Color Rules

蓝色是品牌可信主色。

推荐用于：

- 主 CTA
- 关键操作按钮
- 功能入口
- 重要标签
- 图表主线
- 金融科技感主视觉

推荐色值：

```css
--brand-primary: #1B88EE;
--brand-primary-pressed: #0F78D4;
--brand-primary-focus: #1580E0;
--brand-poster: #3180EC;
--brand-faded: #F0F6FF;
--soft-blue-bg: #EAF4FF;
--surface-page: #ECF4FF;
```

### 6.1.2 Background Color Rules

页面背景不建议通屏纯白，应使用低饱和浅色氛围底。

按场景：

- 策略 / 功能 / 教育类：浅蓝、浅紫蓝
- 活动 / 权益 / 节日类：浅暖色、浅粉、浅橙
- 报告 / 复盘类：浅蓝灰、浅紫蓝
- 诊断 / 工具类：浅蓝灰、科技浅蓝

推荐：

```css
--bg-blue-1: #EAF4FF;
--bg-blue-2: #ECF4FF;
--bg-blue-3: #E8F1FE;
--bg-purple-1: #EEF0FF;
--bg-purple-2: #F1F3FF;
--bg-warm-1: #FFF2ED;
--bg-warm-2: #FFF6E8;
--bg-pink-1: #FDECEF;
```

避免：

- 大面积纯黑
- 高饱和大红
- 高饱和金色
- 大面积深蓝压迫感
- 电商促销撞色

### 6.1.3 Card Color Rules

正文内容必须优先使用白色或近白色卡片承载。

推荐：

```css
--card-main: #FFFFFF;
--card-soft: #F8FBFF;
--card-warm: #FFF8F3;
--card-blue: #F0F7FF;
--card-purple: #F4F3FF;
```

要求：

- 卡片与页面背景有轻微层级差。
- 不使用重描边。
- 不使用高对比强阴影。
- 保证文字可读。

### 6.1.4 Warm Accent Rules

暖色只用于利益点、关键数据和活动提醒，不作为大面积主色。

用于：

- 收益数字
- 优惠券金额
- 活动时间
- 截止提醒
- 关键高亮词
- 图表对比线

推荐：

```css
--warm-orange: #FF8A3D;
--benefit-orange: #FF7A45;
--soft-red: #FA6A55;
--risk-red: #FA440C;
--warning: #EA9500;
```

避免：

- 大面积红色背景
- 红金组合
- 红包雨
- 过度刺激的抢购感

### 6.1.5 Scenario-based Color Palettes

#### 策略介绍页

```txt
浅蓝 / 浅紫蓝 + 白卡 + 品牌蓝 CTA + 少量橙红数据
```

气质：专业、克制、长期、可信。

#### 活动福利页

```txt
浅蓝 / 浅暖色渐变 + 白卡 + 暖色利益点 + 蓝色 CTA
```

气质：有活动感，但不电商化。

#### 节日活动页

```txt
浅橙 / 浅粉 / 米白 + 少量节日暖色 + 蓝色 CTA
```

气质：温暖、有节日感，但不俗气。

#### 定投教育页

```txt
浅蓝绿 / 浅蓝 + 自然色点缀 + 白卡 + 蓝色 CTA
```

气质：长期、生长、陪伴、规律。

#### 报告 / 年度账单页

```txt
浅蓝紫 + 白卡 + 少量金色 / 橙色成就点缀
```

气质：仪式感、可信、复盘感。

#### 功能上线页

```txt
科技浅蓝 + 白卡 + 蓝色按钮 + 少量橙色高亮操作点
```

气质：产品感、效率感、智能感。

#### 权益 / 会员页

```txt
浅蓝 + 浅紫 + 少量金色 / 珠光色
```

气质：专属感、礼遇感，但不过度奢华。

#### 诊断 / 工具页

```txt
浅蓝灰 + 白卡 + 数据图表蓝 + 少量风险橙红
```

气质：专业、分析感、可信。

### 6.1.6 CTA Color Rule

无论页面主题色如何变化，主 CTA 默认使用且慢品牌蓝。

原因：

- 保持 App 内操作一致性
- 降低金融交易动作的不确定感
- 避免活动页过度促销化

除非明确要求，不使用红色、橙色、金色作为主 CTA。

## 6.2 Typography

推荐字体：

```css
font-family: "PingFang SC", "MiSans", system-ui, -apple-system, BlinkMacSystemFont, sans-serif;
```

数字推荐：

```css
font-family: "MiSans", "DIN Alternate", "PingFang SC", system-ui, sans-serif;
```

建议字号：

- Hero 主标题：28px–36px
- 模块标题：18px–22px
- 卡片标题：15px–18px
- 正文：13px–15px
- 辅助说明：11px–12px
- 风险提示：10px–12px
- 关键数据：22px–32px

要求：

- 不使用纯黑，主文本优先 `#333333`
- 次级文字 `#606060`
- 说明文字 `#999999`
- 禁用文字 `#CCCCCC`

## 6.3 Card System

### 6.3.1 常规卡片

```css
.card {
  width: 343px;
  margin: 0 auto 12px;
  padding: 16px;
  border-radius: 16px;
  background: #FFFFFF;
  box-shadow: 0 2px 10px rgba(36, 91, 165, .06);
}
```

### 6.3.2 卡片规则

- 白卡是主要信息承载层。
- 卡片圆角建议 16px–20px。
- 阴影轻柔，不使用厚重投影。
- 卡片间距建议 12px–20px。
- 每张卡只承载一个主要观点。

## 6.4 Hero Image Rules

### 6.4.1 完整氛围图

策略页、活动页、专题页的首屏氛围图必须完整，不允许像 CSS 几何拼图一样破碎。

要求：

- 统一天空 / 背景 / 主视觉关系
- 不出现断层、错位、重复、残缺
- 图像底部与页面背景自然衔接

### 6.4.2 Hero Transition Rules

头图底部必须与页面背景或首张卡片自然过渡。

推荐方式：

- 渐隐过渡
- 雾化过渡
- 首卡上浮
- 背景延续
- 地形 / 水面延展

推荐 CSS：

```css
.hero::after {
  content: "";
  position: absolute;
  left: 0;
  right: 0;
  bottom: 0;
  height: 72px;
  background: linear-gradient(
    180deg,
    rgba(236,244,255,0) 0%,
    rgba(236,244,255,.76) 62%,
    var(--surface-page) 100%
  );
  pointer-events: none;
}
```

### 6.4.3 首卡上浮

- 首张数据卡 / 权益卡可上浮覆盖头图底部。
- 上浮高度建议：16px–32px。
- 首卡圆角建议：16px–20px。
- 首卡与头图之间应是“承接”，不是“断开”。

## 6.5 Icon Rules

- 营销页 icon 优先使用内联 SVG。
- 不依赖外部 icon CDN 作为唯一来源。
- 风格统一：轻量、柔和、低饱和、浅蓝底。
- 不允许空白 icon、破图、emoji、粗糙线框。
- 同一页面 icon 透视、粗细、色彩必须统一。

---

## 6.6 Illustration Color Rules

营销页插画应保持低饱和、轻质感、金融科技感。

推荐：

- 蓝色透明玻璃质感
- 浅紫蓝光效
- 柔和人物肤色和服装色
- 少量橙色金币 / 券 / 收益符号
- 白色高光和轻阴影

避免：

- 高饱和卡通色
- 大红大绿
- 低幼儿童插画感
- 复杂背景抢正文
- 插画色彩与页面背景割裂

## 6.7 Chart Rules

### 6.7.1 Chart Color Rules

推荐：

```css
--chart-primary: #1B88EE;
--chart-blue: #69B1F4;
--chart-orange: #FF9F40;
--chart-warning: #EA9500;
--chart-red: #FA6A55;
--chart-risk: #FA440C;
--chart-gray: #B8C4D6;
--chart-grid: #EDF2F7;
```

避免：

- 同一图表超过 4 个高饱和色
- 红绿强对比作为主要编码
- 过深网格线
- 图表颜色和页面体系割裂

### 6.7.2 Visual Smoothness Rules

图表和示意图应避免明显切角、断裂拼接、粗糙分段。

强约束：

- 仪表盘、环图、进度弧线不得出现明显切角。
- 多段色彩可以表达档位，但段与段之间应柔和过渡。
- SVG 图形优先使用 `stroke-linecap: round`、渐变描边、连续路径实现。
- 不使用粗糙 CSS 拼接造成锯齿、断层或错位。

## 6.8 CTA Rules

- 主 CTA 默认品牌蓝。
- 按钮高度不低于 48px。
- 圆角建议 999px 或 24px。
- 文案必须是明确动作。
- 不制造焦虑，不写“错过血亏”。

---

## 6.9 Risk Disclosure Rules

- 风险提示必须可读。
- 字号建议 10px–12px。
- 颜色可以弱化，但不能不可读。
- 不隐藏、不折叠为唯一展示。
- 投资页、策略页、活动页均需保留相应风险提示。

## 8. Asset Handling Rules

### 8.1 首屏图

- 首屏氛围图不得使用粗糙 CSS 占位图作为最终结果。
- 有真实头图时，应优先嵌入图片或使用可访问路径。
- 无真实头图时，应使用完整 SVG 插画，而不是多层 CSS background 拼接。

### 8.2 本地资源

- 不得引用不存在的本地相对路径图片。
- 如页面依赖本地素材文件夹，必须说明依赖关系。
- 默认输出验证版时，优先生成单文件 HTML。

### 8.3 主理人 / 顾问头像

- 有真实头像时使用真实头像。
- 无真实头像时使用低饱和虚拟头像。
- 禁止留空、破图、默认浏览器占位图。

### 8.4 产品截图

- 截图必须清晰。
- 必须高亮关键操作区域。
- 一张截图只讲一个重点。
- 不直接堆原始长图。

## 9. Page Pattern Library

### 9.1 Strategy Introduction Patterns

#### Pattern 1: 进取策略型策略介绍页

适用：守正出奇、权益增强、信号发车、波动捕捉类策略。

核心结构：

```txt
首屏策略主张
→ 关键数据
→ 策略定位
→ 业绩表现
→ 策略亮点
→ 信号机制
→ 历史验证
→ 适合人群
→ 风险提示
```

重点：

- 优先证明信号逻辑和历史验证。
- 用数据卡、图表和机制图讲清策略。
- 不只堆收益数字。

#### Pattern 2: 稳健安心型策略介绍页

适用：思远安心稳健、稳健配置、低波策略。

重点：

- 首屏风景氛围图，低饱和、安稳。
- 首屏高度约 400px，保证主题和关键数据一屏可见。
- 强调目标、稳健、主理人陪伴。

#### Pattern 3: 现金流定取型策略介绍页

适用：生生不息、月月分红、定期取用、养老现金流。

重点：

- 解释现金流如何产生。
- 强调定取不等于固定收益。
- 冷暖色比例建议约 70% : 30%。
- 视觉可用果树、花朵、水流、阳光、收获。

#### Pattern 4: 陪伴服务型策略介绍页

适用：周周同行、主理人陪伴、定期复盘、社群服务。

重点：

- 谁在陪伴我？
- 每周给我什么？
- 波动时如何沟通？
- 策略调整如何解释？

视觉：同行、路径、山脊线、开阔自然场景。

#### Pattern 5: 长期投资规划型策略介绍页

适用：长赢计划、150份、S 定投、长期配置。

推荐逻辑：

```txt
用户为什么容易亏钱
→ 策略如何筛选
→ 怎么买
→ 买多少
→ 什么时候买
→ 跌了怎么办
→ 谁来陪伴
```

#### Pattern 6: 多资产配置型策略介绍页

适用：全天候、永久组合、全球资产配置。

重点：

- 优先展示收益目标 + 回撤目标。
- 解释跨资产、低相关性、风险分散。
- 使用环图、资产配置卡、长期表现图。

#### Pattern 7: 稳健收益增强型策略介绍页

适用：固收+、稳健增强、闲钱升级。

重点：

- 比现金管理更进一步。
- 债券打底 + 收益增强。
- 用生活场景讲适合人群。

## 11. Document-to-H5 Compression Rules

当输入是完整文档时，不得直接把原文铺满页面。

流程：

1. 提炼一句页面主张。
2. 提炼 3 个以内关键词。
3. 提炼首屏关键信息。
4. 选择最适合的 Pattern。
5. 选择 5–8 个核心模块。
6. 每个模块只保留一个核心观点。
7. 长段落改成标题 + 短说明 + 卡片 / 图示。
8. 复杂机制改成流程图、步骤卡、示意图。
9. 数据必须补充口径。
10. 风险提示完整保留。

## 12. Cursor Generation Rules

### 12.1 生成前必须判断

- 页面类型
- 主目标
- 用户场景
- 转化动作
- 对应 Pattern
- 需要哪些数据口径
- 是否有参考图 / 参考稿

### 12.2 输出要求

- 375px App H5
- 单文件 HTML 优先
- 内联 CSS
- 关键 icon / 图表可展示
- 不依赖不可控外部资源
- 无横向滚动
- 顶部导航、内容区、底部 CTA 同容器

### 12.3 不允许

- 直接生成 PC 页面
- 粗糙 CSS 占位头图
- 外部 icon 加载失败
- 破图
- 大量复制文档原文
- 多个同权重 CTA
- 把活动页做成说明书
- 把报告页做成强促销页
- 把诊断页做成恐吓页

## 13. Generation Checklist

### 13.1 页面目标

- 是否明确页面类型？
- 是否只有一个主目标？
- CTA 是否匹配目标？
- 是否选择了合适 Pattern？

### 13.2 首屏

- 用户一屏内是否知道页面在讲什么？
- 主视觉是否完整？
- 首屏与内容区是否自然过渡？
- 首屏是否没有过度挤压正文？

### 13.3 内容

- 是否按“场景 → 价值 → 证明 → 行动”递进？
- 是否每屏一个核心观点？
- 是否避免长文堆叠？
- 是否进行了移动端阅读化压缩？

### 13.4 视觉

- 是否符合浅色氛围底 + 白卡 + 蓝色 CTA？
- icon 是否精细？
- 图表是否可读？
- 卡片层级是否清楚？
- 是否避免粗糙切角和工程占位感？

### 13.5 合规

- 收益数据是否有来源？
- 是否避免收益承诺？
- 风险提示是否可读？
- 活动规则是否清楚？
- 功能说明是否没有夸大效果？
