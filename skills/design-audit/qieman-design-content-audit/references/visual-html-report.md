# Visual HTML Audit Report

本文件定义页面类核查任务的可视化 HTML 报告规则。

---

## 1. 使用条件

当 Audit Target 是以下任一形式时，默认可生成可视化 HTML：

- HTML 页面
- 生产页面快照
- Figma 导出图片
- 设计稿截图
- PDF 页面
- 长图
- 海报
- 多屏页面拼图

如果用户明确要求“只要文字清单”，可以不生成 HTML。

---

## 2. 报告目标

用户打开一个 HTML 文件即可完成：

```text
查看原页面
→ 看到错误位置
→ 点击编号查看问题详情
→ 按建议逐项修改
```

不要求用户再次打开 Figma、重新导出图片或在长页面中手动搜索字段。

---

## 3. 报告布局

推荐三栏或两栏结构：

### 顶部工具栏

- 项目名称
- Source of Truth
- Target
- 生成时间
- 问题项数量
- 页面标记数量
- P0/P1/P2 数量
- 搜索框
- 优先级筛选
- 页面切换

### 页面预览区

- 展示原页面、HTML 或高清截图
- 保持原始宽高比
- 支持长页面滚动
- 支持 100% / 75% / 50% 缩放
- 标记不可遮挡大面积正文

### 问题详情区

每项显示：

- 编号
- 优先级
- 核查维度
- 页面与模块
- Source 原文
- Target 当前内容
- 差异说明
- 修改建议
- 出现次数
- 每个出现位置的跳转入口

---

## 4. 标注视觉规范

### P0 必须修正

- 红色描边：`#E5484D`
- 半透明红底：`rgba(229, 72, 77, 0.14)`
- 编号圆点：红底白字
- 默认实线

### P1 建议修正

- 橙色描边：`#F59E0B`
- 半透明橙底
- 默认虚线

### P2 可选优化

- 蓝色描边：`#3B82F6`
- 半透明蓝底
- 默认点线

如果用户要求“所有问题均红色标注”，允许统一使用红色，但问题卡仍需保留 P0/P1/P2 标签。

---

## 5. 重复字段标注规则

同一个错误字段在一个页面或多个页面中出现多次时，必须采用“问题分组 + 全部实例标记”。

示例：

```text
问题 AUD-003：
Target 错误字段：“近一年”
Source 标准字段：“近1年”
页面中出现 5 次
```

报告必须：

- 右侧只建立 1 个问题组，避免问题列表重复。
- 页面中生成 5 个独立标记。
- 编号使用：
  - `3.1`
  - `3.2`
  - `3.3`
  - `3.4`
  - `3.5`
- 问题卡显示“共 5 处”。
- 提供“上一处 / 下一处”或 5 个位置按钮。
- 点击任一标记，打开同一个问题组并显示当前出现位置。
- 统计中区分：
  - `问题项：1`
  - `出现位置：5`

不得只标记第一次匹配。

---

## 6. 两种标注模式

### A. DOM 文本标注模式

适用于提供了 HTML 源码或可读取 DOM 的页面。

执行方式：

1. 克隆或嵌入页面 HTML。
2. 使用文本节点遍历查找 Target 错误文字。
3. 对全部精确匹配内容包裹标记元素。
4. 为每个匹配生成独立 occurrence ID。
5. 排除 `script`、`style`、隐藏节点和报告自身节点。
6. 不修改原始业务文本。
7. 默认使用精确匹配；模糊匹配必须标记低置信度。

推荐数据：

```json
{
  "match": {
    "type": "text",
    "value": "近一年",
    "matchAll": true,
    "caseSensitive": true
  }
}
```

### B. 坐标覆盖标注模式

适用于截图、Figma 导出图、PDF 页面和不可读取 DOM 的页面。

每个出现位置记录归一化坐标：

```json
{
  "pageId": "page-2",
  "x": 0.12,
  "y": 0.38,
  "width": 0.36,
  "height": 0.045
}
```

坐标以页面左上角为原点，范围为 0–1。页面缩放时标记同步缩放。

---

## 7. 多页面规则

- 每个页面必须有稳定 `pageId`。
- 问题可以跨多个页面。
- 点击问题位置时自动切换到对应页面。
- 页面标签显示该页问题数量。
- 长页面可以按屏切分，也可以使用单一长图。
- 不得因切屏导致同一字段的重复位置漏标。

---

## 8. 双向联动

### 点击问题卡

- 切换到对应页面
- 滚动到第一处或用户选择的出现位置
- 标记闪烁 1–2 秒
- 页面缩放保持不变

### 点击页面标记

- 激活对应问题卡
- 展示当前 occurrence 编号
- 显示 Source 与 Target 对照
- 高亮当前问题，弱化其他问题

---

## 9. 输出文件规则

推荐输出：

```text
项目名-content-audit.html
```

为便于外发，优先生成单文件 HTML：

- CSS 内联
- JavaScript 内联
- 页面截图使用 Base64 或同目录相对路径
- 不依赖网络 CDN
- 不上传字体文件
- Chrome / Edge / Safari 可打开

如果页面素材过大，可输出：

```text
项目名-content-audit/
├── index.html
└── assets/
```

并打包为 ZIP。

---

## 10. 数据结构

每项 issue 至少包含：

```json
{
  "id": "AUD-003",
  "priority": "P0",
  "dimension": "时间周期表述",
  "sourceText": "近1年",
  "targetText": "近一年",
  "description": "周期格式与需求文档不一致",
  "suggestedFix": "统一修改为“近1年”",
  "occurrences": []
}
```

HTML/DOM 模式可以由 `match` 自动生成 occurrences；截图模式必须显式提供坐标。

---

## 11. 验收标准

- 原页面可直接查看。
- 所有问题均有页面内标记。
- 每个标记都有编号。
- 同一字段重复出现时全部标记。
- 问题项数与出现次数分别统计。
- 问题卡和页面标记可双向跳转。
- Source / Target / 建议修改可直接对照。
- 报告打开不依赖网络。
- 不改变原页面业务文案。
