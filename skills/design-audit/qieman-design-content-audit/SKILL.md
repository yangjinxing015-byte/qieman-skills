# qieman-design-content-audit

且慢需求稿—设计稿—实现稿内容核查 Skill。

## 目标

快速找出明确错误，并输出一个可直接打开的 HTML 核查报告：

- 原设计稿直接显示在报告中
- 只标注确认有问题的位置
- 正确区域不做标记
- 同一错误文字出现多次时，逐个定位并标注
- 点击问题清单可跳转到页面中的准确位置
- 不需要用户再次打开 Figma 或手动查找

---

## 输入

### Source of Truth

用户指定的准确信息源，例如：

- 业务需求文档
- 文案表或数据表
- 业务确认 HTML
- 用户明确指定的生产页面
- 已确认设计稿

### Audit Target

待核查目标，例如：

- Figma 导出图
- 页面截图
- PDF
- HTML
- 生产页面
- 海报、长图或报告

若用户已说明“以某文件为准”，直接执行。

若用户未说明：

- 需求稿 + 设计稿：默认需求稿为准
- 两份设计稿或两个业务版本：先说明无法判断哪版正确

---

## 默认检查范围

只检查明确、可验证的问题：

1. 文案缺失、多出、整句或整段遗漏
2. 标题、正文、按钮、标签、角标不一致
3. 产品名、策略名、活动名错误
4. 金额、百分比、数量、日期、小数位、千分位、正负号
5. 单位、数学符号、时间周期和统计口径
6. CTA 按钮错误
7. 风险提示、免责声明和明显违禁表达
8. 复制组件遗留旧文案、旧数字、旧日期或旧按钮
9. 明显模块遗漏或新增

默认不检查：

- 已确认正确的内容
- 装饰性文字
- 轻微语气差异
- 普通标点差异
- 大小写与全半角
- 纯排版换行
- UI 色彩、字号、间距、圆角
- 像素级视觉还原

---

## 核查流程

```text
确认 Source
→ 提取 Source 的关键标题、数字、按钮和风险提示
→ 查看 Target 对应位置
→ 判断明确错误、遗漏和组件残留
→ 为每个问题记录准确位置
→ 生成 HTML 标注报告
```

不要输出长篇过程分析。

不要复述全部需求文档。

不要展示正确项。

---

## 输出

默认输出：

```text
项目名-content-audit.html
```

使用模板：

```text
assets/visual-audit-report.html
```

HTML 报告必须包含：

- 原设计页面或截图
- 页面内错误标记
- 问题编号
- Source 原文
- Target 当前内容
- 差异说明
- 建议修改
- 出现次数
- 每个位置的跳转入口

---

## 定位方式

### HTML 页面

优先使用可见文本节点定位：

- 排除 `script`、`style`、`noscript` 和隐藏节点
- 只包裹实际错误文本
- 不做全文字符串替换
- 不改写原始文案
- 不破坏原页面布局和事件

### 截图、Figma 导出图、PDF 页面

使用归一化坐标：

```json
{
  "pageId": "page-1",
  "x": 0.12,
  "y": 0.38,
  "width": 0.36,
  "height": 0.045
}
```

坐标范围为 0–1，页面缩放时标记同步缩放。

---

## 重复文字

相同文字可能在全文出现多次，因此不得只写文字描述，也不得只标第一处。

例如同一错误出现 4 次：

```text
问题项：1
实际标记：4
```

页面标记：

```text
3.1
3.2
3.3
3.4
```

要求：

- 每个实际错误位置都标出
- 右侧合并为一个问题组
- 显示“共 4 处”
- 每处都有独立跳转入口
- 相同文字中只有部分位置错误时，只标有问题的实例

---

## 缺失与多出

### 缺失内容

需求稿有、设计稿没有时：

- 在最接近的应出现模块使用红色虚线框
- 类型标记为“缺失内容”
- 右侧展示缺失原文
- 不在无关位置放置标记

### 多出内容

设计稿有、Source 没有时：

- 直接框选多出内容
- 类型标记为“多出内容”
- 说明 Source 中未找到对应内容

---

## 优先级

### P0 必须修正

- 产品名、策略名、活动名错误
- 文案缺失、多出或整段遗漏
- 金额、比例、收益、回撤、日期、期限错误
- 单位、正负号、数据区间或时间口径错误
- CTA 错误
- 风险提示缺失或错误
- 复制组件残留其他业务内容

### P1 建议修正

仅在用户明确要求检查格式时使用：

- 标点
- 大小写
- 全半角
- 顺序不一致但未改变业务含义

---

## 无法确认

以下情况不猜测：

- 截图太小或文字模糊
- 页面未提供
- Source 自身矛盾
- 动态数据缺少核查时点
- 关键字段被遮挡

无法确认项放在右侧单独说明，不在页面上误标。

---

## 推荐调用

```text
调用 qieman-design-content-audit，
以需求文档为准，核对设计稿。
输出 HTML 核查报告，只标注有问题的位置。
同一错误文字出现多次时，按实际位置分别标注。
```

---

## 强制规则

- 不擅自改写 Source
- 不猜测看不清的文字
- 只标注确认有问题的位置
- 不展示正确项
- 不做无关视觉评价
- 同一错误的所有实际位置必须逐一核对
