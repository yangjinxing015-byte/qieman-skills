# qieman-insurance-design

## 1. Positioning

`qieman-insurance-design` 是且慢保险业务的垂直设计 Skill。
它继承 `qieman-ui-design` 的品牌 Token、基础组件和移动端规范，只增加保险业务专属的：

- 保险产品介绍页的信息架构
- 保险 Hero 的构图与融合规则
- 基础 UI Icon / 保险专业视觉 Icon 的分层
- 轻量保险插画、医疗场景插画、信息插画
- 保险顾问、家庭、长辈人物资产
- 保险信息可视化决策
- 保险文案、数据、责任范围的严格保护
- 保险页面专项设计验收

**设计目标：**让用户更快理解“这是什么保险、适合谁、保什么、怎么用、有什么限制”，而不是追求过度营销或装饰。

```text

↓

08 执行保险内容审核
↓

```

**原则：先解决信息理解，再解决视觉表现。**

## 5. Insurance Type Routing

### 5.1 医疗险
优先表达：谁能投、保什么、医院/药品/院内院外范围、免赔额、报销比例、保额、续保/等待期/健康告知、就医与理赔服务。

### 5.2 重疾险
优先表达：疾病责任层级、给付逻辑、保障期限、轻症/中症/重疾关系、等待期与免责。

### 5.3 意外险
优先表达：意外身故/伤残、意外医疗、特定交通/场景责任、责任范围与限制。

### 5.4 寿险
优先表达：家庭责任、保障期限、保额与家庭财务缺口、责任关系。

### 5.5 年金险 / 储蓄型保险
优先表达：领取节奏、现金流结构、时间周期、领取条件、演示数据口径与非保证说明。

## 7. Hero Guidelines（重点）

保险 Hero 必须兼顾：**信息清晰、人物融合、左右平衡、自然过渡**。

### 7.1 Hero 类型

#### A. 家庭保障型
适合家庭医疗险、少儿险、家庭综合保障。
- 一家三口或全家人
- 保护罩 / 盾牌 / 家庭轮廓作为单一主语义

#### B. 长辈 / 父母型
适合父母医疗险、老年医疗险、防癌医疗等。
- 老年夫妻或单个长辈
- 健康、整洁、安心，不病弱

#### C. 精准人群型
适合身体异常、特定年龄、特定群体产品。

#### D. 保障强化型
人物/保单为主体，仅叠加一个强保障符号。

### 7.2 Hero 强规则（验证版已确认）
1. 默认采用 **左侧文案 + 右侧人物/插画** 的结构。
2. 文案区与人物区必须明确分区，不得相互遮挡。
3. 左侧文案块与右侧人物块应 **垂直居中对齐**，保证视觉中心一致。
4. 两侧视觉重量需接近，避免人物过小或出现大面积无效留白。
5. 标题、卖点、标签必须保留清晰安全区，不通过压暗图片来解决可读性问题。
6. 人物主体应靠右放置，主标题始终左对齐。

### 7.3 Hero 背景融合规则（验证版已确认）
1. Hero 必须是一个整体化头图，不允许出现“独立矩形人物图贴到背景上”的感觉。
2. 人物插画优先使用 **透明底资产**。
3. 若使用带背景插画，其背景色必须与 Hero 主背景同色系，并通过遮罩、羽化或渐变自然融合。
4. Hero 底部与正文内容区之间必须自然过渡，使用渐变、柔光或雾化方式衔接，避免明显断层。
5. 人物后方的盾牌/守护氛围建议由页面背景或 CSS 氛围层生成，而不是再叠一张独立小底图。

### 7.4 参考基准
当前基础验证标准以：
`众民保百万医疗险2026_保险Skill验证版_v8_内嵌Icon.html`
中的 Hero 处理为基准。

## 8. Icon System

保险设计采用两层 Icon 体系，严禁混淆。

### 8.1 L1：基础 UI Icon
统一使用 **Remix Icon v4.6.0**。

适用：返回、关闭、展开、提示、问号、信息、电话、客服、日历、文件、表单、用户、箭头、步骤、状态。

规则：
- 默认 `-line`
- 选中/成功态才使用 `-fill`
- 同一页面不混用其他 icon font

### 8.2 L2：保险专业视觉 Icon
用于产品卖点、保障责任、保险专业概念。

默认风格：
- 蓝橙双色
- 轻 3D / 柔和渐变
- 白底或透明底
- 正面或轻 3/4 视角
- 圆润几何体
- 轻高光 + 轻软阴影

适合元素：
- 盾牌 + 医疗十字
- 药品 / 院外药
- 病历 / 健康档案
- 计算器 / 保费测算
- 保障清单 / 保单
- 限制 / 禁用语义

### 8.3 Icon 必须落位的模块（新增强规则）
以下模块优先必须带 Icon，不可只有纯文字：
- 产品核心卖点
- 适合谁买 / 用户痛点
- 保障责任摘要
- 理赔流程 / 投保流程
- 服务权益 / 增值服务

### 8.4 本地预览稳定性规则（验证版已确认）
若输出是 HTML 且需要支持本地 `file://` 打开：
- 基础 Icon 不应完全依赖在线 CDN 才能显示。
- 优先使用 **内嵌 SVG** 或可稳定离线显示的图标方案。
- 若使用 Remix Icon CDN，需同时考虑本地离线预览失败的兜底方案。

## 9. Illustration System

### 9.1 默认：轻量保险插画
用户未指定风格时优先使用。

特征：
- 白色 / 极浅蓝背景
- 蓝色主色，暖橙少量强调
- 轻 3D + 半扁平
- 圆润轮廓
- 柔和渐变
- 轻阴影
- 通透、简洁、适合移动端卡片

### 9.2 医疗场景插画
适合住院、就医、病床、输液、药品等具体医疗场景。
- 一个主场景 + 1–3 个辅助元素
- 不做复杂医院环境

### 9.3 信息插画
适合多项保障关系、复杂机制。
中心主体可为：保单、盾牌、保障卡；外围最多 3–4 个信息节点。

### 9.4 插画选择规则
```text
基础操作/提示 → 基础 UI Icon
单一保险卖点 → 保险专业视觉 Icon
页面模块解释 → 轻量保险插画
具体就医/住院情境 → 医疗场景插画
多项保障关系 → 信息插画
人群/服务/情绪主题 → 人物主视觉
```

## 10. Persona System

### 10.1 保险顾问
定位：**专业顾问 / 服务陪伴者，不是强销售。**

#### 男顾问：许安
- 约 30 岁
- 温暖亲和、理性可靠、耐心细致
- 蓝色西装、浅色衬衫、小面积暖金点缀

#### 女顾问：林知暖
- 约 28 岁
- 知性亲和、细腻共情、专业沉稳
- 蓝色职业套装、工牌、平板

### 10.2 家庭人物

#### Family-3：一家三口
- 年轻父母 + 1 名儿童
- 适合家庭医疗险、少儿险、家庭保障
- 可用“人物居中守护型”或“偏侧头图型”

#### Family-5 / Multi-generation：全家人
- 默认：年轻父母 + 儿童 + 2 位老人
- 也可按文案扩展为 6 人
- 适合多代同堂、全家保障

#### Senior：长辈 / 老年夫妻
- 健康、自然、整洁、亲和
- 不画成虚弱、卧床、焦虑的默认形象

### 10.3 人物视觉原则
- 轻 3D / 柔和 C4D
- 蓝白主调 + 少量暖色服装
- 自然互动、陪伴感
- 不过度摆拍，不低幼，不病弱

## 11. Insurance Data Visualization

信息可视化继承用户已确认的保险设计方案，不另起一套装饰风格。

| 信息 | 默认表现 |
|---|---|
| 等待期 / 投保 / 理赔流程 | 时间轴 / Step Flow |
| 院内 vs 院外 | 双栏对比 |
| 保障责任差异 | 对比卡 / 对比表 |
| 过去 vs 现在 | 双场景插画 + 对比信息 |
| 3–4 个产品优势 | 3 项卡片 / 2×2 卡片 |
| 保额 / 免赔额 / 保费 | 大数字 + 简洁关系图 |
| 年龄 / 保障期限 | 区间轴 / 时间范围 |
| 保障组成 | 环图 / 分层结构 |
| 多阶段机制 | 时间线叙事 |
| 单一核心数据 | 数字卡 |

规则：
- 一图一义，移动端优先。
- 图表放在有明确主题的卡片中。
- 数据来源、统计口径、时间范围不得被省略。
- 保险页面不要用 K 线、交易屏、收益曲线做默认装饰。

## 12. Existing Design Optimization Rules（新增）

当用户提供“已有设计稿 / 现有 HTML / 已有标准版式”并要求优化时：

1. **优先继承原稿尺寸、版式节奏、模块顺序和排版密度。**
2. 不得因为补充 Icon / 插画 / Hero 优化而擅自改整体画布比例。
3. 已有验证有效的模块，只做局部增强，不整体推翻重做。
4. 若用户特别指出“原版尺寸更好”，则尺寸视为强规范。
5. 优化目标应聚焦于用户指出的问题，例如：
   - Hero 左右排布
   - 背景衔接
   - Icon 补充
   - 文案遮挡

## 13. Content Protection & Compliance

这是本 Skill 的最高优先级规则。

### 13.1 不得擅自修改的内容
若用户提供标准文案/产品材料，以下内容必须原样保护：
- 产品名称
- 保额
- 保费
- 免赔额
- 报销比例
- 等待期
- 保障期限
- 投保年龄
- 医院范围
- 药品范围
- 健康告知
- 免责条款
- 续保条件
- 保障责任
- 理赔条件
- 疾病名称/数量
- 服务范围
- 风险说明
- 数据来源与时间口径

### 13.2 禁止行为
- 不增加用户未提供的保障责任。
- 不扩大承保范围。
- 不把“可能/符合条件可”改成“可以/一定”。
- 不把演示数据表达成保证结果。
- 不为了营销标题而改变保险事实。
- 不隐藏重要免责、限制、风险说明。

### 13.3 缺失数据
若原型必须占位而用户未提供数据：
- 使用 `XX 万`、`XX 天`、`待确认` 等明显占位。
- 不伪造真实感数字。

## 14. Visual Rules & Avoidances

### 14.1 页面气质
- 专业
- 可信
- 亲和
- 清爽
- 克制
- 通透

### 14.2 默认页面语言
- 浅底 + 白色卡片
- 蓝色为主
- 暖橙用于重点数字、提醒、正向强调
- 浅紫用于弱辅助或过去/历史信息
- 阴影轻

### 14.3 保险视觉禁用项
除非用户明确要求，否则避免：
- 满屏盾牌 / 爱心 / 医疗十字堆叠
- 大量医疗 Icon 堆积
- 低幼卡通
- 手绘线稿
- 高饱和糖果 3D
- 强塑料/玩具质感
- 复杂医院背景
- 现金、人民币、金币作为保险主视觉
- K 线、交易屏、上涨箭头等投资类装饰
- 与保障信息无关的装饰性 3D 物件

**优先表达具体保障场景，而不是抽象“保险感”。**

## 15. Output Modes

### 15.1 页面生成
输出高保真 HTML / UI，遵循用户原始文案。

### 15.2 方案分析
输出：信息层级判断、方案优缺点、推荐方案、精确修改建议。

### 15.3 插画 / Icon 任务
先判断属于：
- 基础 UI Icon
- 保险专业视觉 Icon
- 轻量保险插画
- 医疗场景插画
- 信息插画
- 人物主视觉

### 15.4 审核任务
从四层检查：
- 内容是否准确
- 页面是否可读
- 视觉是否统一
- 保险表达是否误导

## 16. Final Audit Checklist

### 内容检查
- 文案是否与标准稿一致？
- 关键数字是否一致？
- 责任、限制、免责是否遗漏？

### Hero 检查
- 是否左文右图？
- 是否互不遮挡？
- 是否垂直居中对齐？
- 人物与背景是否自然融合？
- Hero 与正文是否自然过渡？

### Icon 检查
- 关键模块是否有 Icon？
- Icon 是否能在本地离线预览正常显示？
- UI Icon 与专业视觉 Icon 是否用对？

### 页面检查
- 是否遵守 qieman-ui-design？
- 是否保持移动端阅读友好？
- 若基于现有稿优化，是否保留了原尺寸与结构？

### 保险表达检查
- 是否夸大保障？
- 是否生成了未提供的产品事实？
- 是否弱化了风险或重要说明？
