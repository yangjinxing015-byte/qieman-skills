# qieman-design-vip

且慢高净值私域视觉 Skill。

用于生成且慢 VIP、高净值用户、财富管理、投资圈层、私域传播、朋友圈营销等场景的视觉内容。

覆盖：

- 9:16 单张完整 VIP 海报
- 单张无字背景图
- H5 头图 / 页面主视觉
- 多张系列海报
- 300万+ 门槛、席位、圈层主题
- 信息源、投研观点、全球视野、长期陪伴
- 基础 3×3 朋友圈九宫格
- 九宫格拆分输出
- **Style 1：一大三小独立图**
- **Style 2：一大三小连续图**
- 即梦 / Midjourney / SDXL / ChatGPT Image / Firefly 等生图提示词

本 Skill 保留原有 VIP 场景能力。

详细规则尽量放在 `references/` 中按任务读取，但九宫格 Style 路由、尺寸和关键约束必须以本文件为最高运行规则之一。

---

# 1. 全局规则优先级

任何任务均按以下顺序执行：

1. 用户当前明确指令
2. 用户提供的文案、顺序、尺寸、参考图
3. 用户明确指定的 Mode / Style
4. 本 Skill 对应任务模式规则
5. 品牌与金融合规
6. 默认版式和视觉建议

## 核心原则

不得使用默认模板覆盖用户已经明确给出的内容。

用户已经提供的信息不得重复询问。

如果用户明确指定：

- 尺寸
- Style
- 文案
- 构图
- 色调
- 图像位置
- 留白位置
- Logo 使用方式
- 是否带字

必须严格执行。

---

# 2. 统一生成原则

## 2.1 文案与视觉解耦

默认情况下，AI 生图模型优先负责：

- 场景
- 背景
- 主视觉
- 主符号
- 光影
- 材质
- 氛围
- 金融意象
- 无字视觉资产

确定性排版工具、HTML、设计软件优先负责：

- 准确中文
- 官方 Logo
- 标题
- 副标题
- 数字
- 九格结构
- Slogan
- 风险提示
- 精确字号
- 精确边距

只有用户明确要求：

> 生图时直接带文字

才允许采用直接带字模式。

涉及重要中文、数字、金额、产品名称、合规文案时，不得依赖生图模型保证准确性。

---

## 2.2 低复杂度构图

默认构图公式：

```text
1 个主题判断
+
1 个视觉母题
+
1 个主要视觉焦点
+
0–2 个辅助元素
+
0–1 个轻金融暗示
```

避免：

```text
多个金融元素
+
多个装饰物
+
多个抽象符号
+
多个信息卡片
+
复杂背景
```

同时出现。

高级感主要来自：

- 比例
- 留白
- 材质
- 光线
- 克制
- 空间尺度
- 信息密度控制

而不是元素堆叠。

# 3. 任务模式路由

收到任务后，先识别主任务 Mode。

原则上每个任务只选择一个主 Mode，不混用主流程。

---

## Mode A — 单张完整 VIP 海报

### 触发

用户要求：

- 海报
- 宣传图
- 完整成稿
- 竖版营销视觉

且没有明确说明只需要背景。

### 默认规格

```text
1080 × 1920 px
9:16
```

用户指定尺寸时，以用户尺寸为准。

### 流程

```text
确定主题
→
判断页面结构
→
选择视觉母题
→
生成无字主视觉
→
准确排版 Logo / 标题 / Slogan / 风险提示
→
输出完整成稿
```

### 必须读取

- `references/vip-poster-page-rules.md`
- `references/design-tokens.md`
- `references/visual-language.md`
- `references/compliance.md`

---

## Mode B — VIP 无字背景 / H5 主视觉

### 触发

用户明确要求：

- 背景图
- 不要文字
- 不要 Logo
- H5 头图
- 页面主视觉
- Banner 背景

### 输出

- 按用户指定尺寸
- 未指定时竖版默认 `1080×1920`
- 根据后续排版预留安全区
- 不生成文字
- 不生成伪 Logo
- 不生成风险提示
- 一个画面只建立一个主要视觉焦点

### 必须读取

- `references/vip-poster-page-rules.md`
- `references/visual-language.md`
- `references/prompt-templates.md`

---

## Mode C — 多张 VIP 系列海报

### 触发

用户要求：

- 2 张及以上海报
- 一组视觉
- 系列视觉
- 多方案
- 多张同主题图

### 要求

系列之间保持：

- 品牌体系统一
- 色彩逻辑统一
- 字体统一
- Logo 规则统一
- 页面收口统一

但每张必须：

- 使用不同视觉母题
- 改变核心主体
- 改变空间关系
- 改变隐喻方式

不得只通过：

- 换角度
- 换位置
- 换颜色
- 更换一两个小元素

制造所谓不同方案。

### 必须读取

- `references/vip-poster-page-rules.md`
- `references/visual-language.md`
- `references/prompt-templates.md`

# 4. 九宫格 Style 系统

“九宫格”在本 Skill 中不再只指传统 3×3。

目前存在三种 Style：

| Style | 名称 | 核心结构 |
|---|---|---|
| Style 0 | 基础 3×3 九宫格 | 9 张方图 |
| Style 1 | 一大三小独立图 | 1 张横图 + 3 张独立方图 |
| Style 2 | 一大三小连续图 | 1 张横图 + 1 张连续长图，后切 3 张 |

---

# 5. 九宫格 Style 路由规则

## 优先级

如果用户明确说：

```text
Style 0
Style 1
Style 2
```

必须直接执行指定 Style。

不得自行修改。

---

## 自动识别 Style 1

以下表达默认识别为 **Style 1**：

- 一大三小独立图
- 横图 + 三张独立小图
- 1 张横图 + 3 张 icon 图
- 三张小图分别生成
- 下方三张不是连续图
- 四张独立图片
- 上面一张，下面三张独立图

---

## 自动识别 Style 2

以下表达默认识别为 **Style 2**：

- 一大三小连续图
- 下方是一整张横图
- 三张小图其实是一张长图
- 2400×800
- 后续自己切成三张
- 连续场景
- 三张拼起来是一张完整画面
- 不要三栏
- 不要三个独立卡片

---

## 自动识别 Style 0

以下情况默认使用 **Style 0**：

- 用户明确说传统九宫格
- 用户给出完整 9 条文案
- 明确要求 3×3
- 明确要求九张 1:1 图
- 明确要求拆成九张

---

## 未指定 Style

如果用户只说：

> 做一个九宫格

且没有其它足够信息判断 Style：

默认走：

```text
Style 0 — 基础 3×3 九宫格
```

不得默认切换 Style 1 或 Style 2，以保证旧任务兼容。

# 8. Style 0 — 基础 3×3 九宫格

## 定义

传统九宫格。

最终共：

```text
9 张独立 1:1 方图
```

整体构成：

```text
3 × 3
```

---

## 默认尺寸

预览总图：

```text
1080 × 1080 px
```

高清总图：

```text
3240 × 3240 px
```

拆分后每张：

```text
1080 × 1080 px
```

---

## 默认流程

```text
锁定 9 条文案及顺序
→
规划九格叙事
→
建立统一视觉系统
→
生成视觉背景
→
准确排版
→
输出 3×3 总图
→
需要时拆分 9 张
```

---

## Style 0 要求

- 九格整体必须像同一个 Campaign
- 不得九张使用完全相同构图
- 不得只换文字
- 每张可使用不同视觉隐喻
- 色彩、光线、材质需保持统一
- 文案顺序不得擅自改变

## 必须读取

# 9. Style 1 — 一大三小独立图

## 9.1 定义

Style 1 是一套高净值朋友圈营销视觉结构。

最终输出：

```text
1 张横版主视觉
+
3 张独立 1:1 小图
```

共：

```text
4 张独立图片
```

三张小图彼此独立。

它们不是同一张长图切割而成。

---

## 9.2 固定尺寸

### 上方横版主视觉

```text
1280 × 720 px
```

比例：

```text
16:9
```

### 强规则

高度必须严格：

```text
720 px
```

不得为了整体组合效果：

- 拉高
- 压缩
- 改成近似比例
- 生成 1280×800
- 生成 1280×900
- 生成其它高度

---

## 9.3 下方三张独立小图

每张尺寸：

```text
800 × 800 px
```

共三张：

```text
800×800
800×800
800×800
```

三张分别独立生成。

---

## 9.4 可选组合预览

如需生成完整组合预览，可使用：

```text
2400 × 2150 px
```

其中：

上部：

```text
2400 × 1350
```

对应原始：

```text
1280 × 720
```

下部：

```text
2400 × 800
```

由：

```text
3 × 800 × 800
```

并排组成。

注意：

**组合预览尺寸仅用于展示版式关系。**

最终交付尺寸仍以：

```text
1280×720
+
3 × 800×800
```

为准。

---

# 10. Style 1 横图构图规则

## 主标题位置

横版主标题必须位于：

```text
画面左侧区域
```

推荐：

- 左对齐
- 左侧集中排版
- 左上 / 左中
- 保留充分呼吸感

禁止：

- 标题居中
- 标题放右侧
- 标题与右侧主体互相挤压
- 主标题跨越主体
- 为视觉主体牺牲文字空间

---

## 主体位置

主要视觉主体原则上：

```text
位于画面右侧
```

左侧：

```text
承担标题 / 副标题
```

右侧：

```text
承担核心场景 / 人物 / 金融视觉
```

形成：

```text
左文
+
右图
```

的稳定关系。

---

## 横图文案

默认允许：

```text
主标题
+
副标题
```

不得自行增加：

- 第三层说明
- 营销标签
- 英文装饰
- 虚构数据
- 装饰性小字
- 未经用户允许的 CTA

---

# 11. Style 1 三张独立小图规则

三张小图必须：

- 各自拥有完整构图
- 各自拥有明确焦点
- 各自可单独发布
- 单独观看时视觉完整
- 保持统一色调
- 保持统一材质
- 保持统一光影
- 保持统一 Campaign 识别度

但不得：

- 三张复制同一构图
- 三张只更换 icon
- 三张只改变物体位置
- 三张完全同一背景
- 三张看起来像同一张长图被切开

---

## Style 1 小图视觉关系

正确：

```text
统一视觉系统
+
不同主视觉
+
不同表达方式
```

错误：

```text
完全相同背景
+
更换三个 icon
```

---

## 小图文字

如用户提供三条四字文案：

每张小图默认只出现：

```text
1 条核心四字文案
```

不得增加自创文案。

---

# 12. Style 2 — 一大三小连续图

## 12.1 定义

Style 2 的上图规则与 Style 1 相同。

区别位于下方。

最终输出：

```text
1 张 1280×720 横版主视觉
+
1 张 2400×800 连续横图
```

用户后续将：

```text
2400×800
```

等分切成：

```text
800×800
+
800×800
+
800×800
```

---

# 13. Style 2 固定尺寸

## 上方

```text
1280 × 720 px
```

高度固定：

```text
720 px
```

---

## 下方

必须一次性生成：

```text
2400 × 800 px
```

禁止分别生成：

```text
3 张 800×800
```

再拼接。

必须从一开始就按：

```text
一张完整 2400×800 画面
```

进行构图。

---

# 14. Style 2 连续长图核心原则

下方长图必须是：

```text
一个完整场景
```

或：

```text
一个完整视觉母题
```

或：

```text
一个连续空间
```

三段只是后续裁切关系，不是设计结构。

---

## 禁止设计成

- 三个独立 icon
- 三张卡片
- 三个并列模块
- 三个独立场景
- 三个方框
- 三栏布局
- 三个底色区域
- 三段明显不同背景
- 明显分割线
- 明显纵向边界
- 卡片式信息架构

---

## 正确结构

```text
一个整体背景
+
一个连续光影
+
一个完整空间
+
一个统一金融隐喻
+
左右自然延展
```

即使切成三张之后，每张依然能看到同一个整体视觉体系。

---

# 15. Style 2 文案安全区

Style 2 根据用户提供文案数量分两种情况。

---

## 情况 A：只有一个核心文案

文案优先位于：

```text
2400×800 中央区域
```

推荐安全区：

```text
x = 800–1600
```

即后续中间切片承担核心信息。

左右区域作为同一场景自然延展。

---

## 情况 B：用户提供三条四字文案

允许分别放置在：

```text
左 800
中 800
右 800
```

三个裁切安全区中。

但必须注意：

**文字分区不等于视觉分区。**

画面依然必须是：

```text
一张完整连续视觉
```

不得因为三条文案而设计成三栏。

---

# 16. Style 1 与 Style 2 的关键区别

| 项目 | Style 1 | Style 2 |
|---|---|---|
| 上图 | 1280×720 | 1280×720 |
| 下图 | 3 张 800×800 | 1 张 2400×800 |
| 小图关系 | 独立 | 连续 |
| 构图 | 3 个独立构图 | 1 个完整构图 |
| 是否可分别生成 | 是 | 否 |
| 是否有连续空间 | 不要求 | 必须 |
| 是否允许三张不同背景 | 是，但需统一体系 | 否 |
| 是否允许明显三栏 | 不涉及 | 禁止 |
| 最终发布 | 4 张独立图 | 上图 + 长图切3张 |

# 17. Style 1 / Style 2 高净值视觉定位

新增两种 Style 主要用于：

- 资产 300 万+ 用户
- 高净值投资者
- 私享圈
- 投资交流圈
- 高端财富管理
- 稀缺资源
- 专属服务
- 投研信息
- 认知升级
- 长期投资
- 高质量投资圈层

视觉必须传达：

```text
高净值
+
尊享
+
稀缺
+
理性
+
金融专业
+
高品质生活
```

但不得做成传统奢侈品广告。

# 18. Style 1 / Style 2 色彩规则

相比传统 VIP 海报，新九宫格 Style 不建议长期使用极深黑蓝。

优先轮换：

### 品牌浅蓝

```text
#1B88EE
+
浅蓝白
+
少量香槟金
```

### 浅蓝金

```text
浅蓝
+
银白
+
浅金
```

### 暖金蓝

```text
暖灰
+
香槟金
+
品牌蓝
```

### 明亮品牌蓝

```text
品牌蓝
+
白
+
局部金色
```

### 浅奢暖色

```text
米白
+
浅金
+
少量深蓝
```

---

## 禁止

连续多轮重复：

```text
深蓝黑
+
金色
+
玻璃物体
+
城市背景
```

这一固定组合。

# 19. 品牌核心色

基础品牌色仍保留：

- 品牌蓝：`#1B88EE`
- 深蓝：`#0A1F3D`
- 黑蓝：`#0D1526`
- 理性蓝：`#1A3A5C`
- 浅蓝白：`#E8F2FA`
- 香槟金：`#C9A962`
- 浅金：`#E8D5A3`
- 风险提示灰：`#999999`

---

## 默认比例

普通 VIP 海报可参考：

```text
蓝 / 黑蓝 75%–88%
白 / 浅色 8%–18%
金色 3%–8%
```

但 **Style 1 / Style 2 不强制使用深色大底**。

如果用户要求：

- 更明亮
- 更通透
- 更柔和
- 浅蓝
- 暖金
- 品牌蓝

则优先执行用户要求。
