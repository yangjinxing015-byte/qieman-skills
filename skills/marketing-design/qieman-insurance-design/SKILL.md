# qieman-insurance-design

## 1. Positioning

`qieman-insurance-design` 是 `marketing-design` 下的 **L2 保险垂类 Skill**。

它不再承担通用 H5 / UI 设计规则，而是在 `qieman-business-content-design` 的基础上，仅增加保险业务特有能力：

- 保险产品信息架构与险种路由
- 保险 Hero 构图与保障语义
- 保险专业 Icon / 插画 / 人物资产
- 保险保障责任与规则类信息可视化
- 保险事实、责任、限制、免责等内容保护
- 保险页面专项验收

**核心目标：**帮助用户快速理解“这是什么保险、适合谁、保什么、怎么用、有哪些限制”，而不是追求过度营销包装。

## 2. Dependency & Rule Priority

```text
qieman-brand-guidelines
        ↓
qieman-ui-design
        ↓
qieman-business-content-design  (L1 通用业务内容页母 Skill)
        ↓
qieman-insurance-design         (L2 保险垂类)
        ↓
具体保险页面 / 保险视觉任务
```

### 2.1 本 Skill 默认继承的通用能力

以下规则统一由 `qieman-business-content-design` 提供，本 Skill **不得复制、重写或另起一套**：

- 移动端业务内容页基础布局、Section 节奏、页面安全区
- 品牌 Token、Typography、Spacing、Radius、Shadow
- Button / Card / Tag / Input 等基础组件
- 同层级 KPI 等权展示规则
- 通用数据卡、对比卡、时间线、图表基础规则
- 原型 / 标准稿的内容与结构保护原则
- 固定吸底 CTA 的全局样式
- HTML / CSS / JS / Responsive / 本地预览基础规范
- 通用设计走查与内容完整性检查

### 2.2 冲突优先级

当规则冲突时，按以下优先级执行：

```text
用户明确要求 / 标准文案 / 官方产品事实
    > 保险业务安全与合规规则
    > qieman-insurance-design 专属规则
    > qieman-business-content-design
    > qieman-ui-design / qieman-brand-guidelines
    > 原型视觉样式
```

**原型决定内容与业务逻辑，不自动决定最终视觉样式。**

## 5. Insurance Page Information Architecture

页面基础骨架由 `qieman-business-content-design` 管理；本节仅定义保险内容的默认业务顺序。

当用户未给出明确结构时，可按下列顺序组织：

```text
Hero：产品是什么 / 适合谁 / 核心价值
↓
产品摘要：关键保障与投保门槛
↓
为什么需要 / 用户风险场景
↓
核心保障责任
↓
关键规则 / 与常规方案的差异
↓
增值服务 / 顾问服务
↓
投保条件 / 健康告知 / 限制
↓
FAQ
↓
风险与重要说明
↓
继承母 Skill 的固定吸底 CTA
```

### 5.1 保险信息层级原则

- 先结论，再解释规则。
- “保什么”必须比“为什么好看”优先。
- 责任、限制、免责不得被弱化到装饰层级。
- 每个模块只解决一个核心保险问题。
- 高密度表格优先转为分组卡片 / 对比结构，但不得改变原始事实。

## 6. Insurance Hero

保险 Hero 是本 Skill 的专属能力之一。

### 6.1 默认构图

默认采用：**左侧文案 + 右侧人物 / 插画**。

强规则：
1. 文案与人物明确分区，不相互遮挡。
2. 左右主体垂直居中，视觉重量接近。
3. 主标题保持清晰安全区，默认左对齐。
4. 人物优先透明底，避免“矩形图片贴在背景上”。
5. 人物背景与 Hero 主背景必须自然融合。
6. Hero 与正文之间通过渐变 / 柔光 / 雾化自然过渡，避免硬切断层。
7. 避免大面积无效留白，也避免人物压迫文案。

### 6.2 Hero 类型

#### A. 家庭保障型
适用：家庭医疗险、少儿险、家庭综合保障。

建议：一家三口 / 多代家庭 + 单一“守护”语义。

#### B. 长辈 / 父母型
适用：父母医疗险、老年医疗险、防癌医疗等。

人物应健康、自然、整洁，不默认表现病弱、卧床或焦虑。

#### C. 精准人群型
适用：身体异常、特定年龄、特定投保条件等产品。

视觉重点应是“仍有选择 / 更适配”，避免制造健康恐惧。

#### D. 保障强化型
人物 / 保单为主体，只叠加一个主要保障符号，不堆叠盾牌、医疗十字等元素。

### 6.3 Hero 不得做

- 不为“保险感”堆满盾牌、十字、药盒。
- 不用现金、金币、收益曲线作为保险主视觉。
- 不通过大面积压暗人物图解决文字可读性。
- 不将人物缩成右下角装饰物。

## 7. Insurance Icon System

保险设计分两层 Icon：

### 7.1 基础 UI Icon

统一继承 `qieman-ui-design`，图形来源优先使用 **Remix Icon v4.6.0**。

适用：返回、关闭、展开、提示、问号、信息、电话、客服、日历、文件、用户、箭头、状态等。

- 默认使用 line 风格。
- 同一页面保持线宽、尺寸、视觉重量一致。
- HTML 需要本地稳定预览时，优先内嵌 SVG，不依赖单一在线 CDN。

### 7.2 保险专业视觉 Icon

用于保险卖点、保障责任、专业概念和场景语义。

默认视觉：
- 蓝橙双色
- 白底 / 透明底
- 半扁平 + 轻 3D / 柔和渐变
- 正面或轻 3/4 视角
- 圆润、简洁、软阴影
- 同组尺寸、朝向、视角、光影一致

典型语义：
- 大病 / 医疗
- 意外保障
- 养老规划
- 教育规划
- 院外药
- 病历 / 健康档案
- 保单检视
- 保费 / 养老 / 教育测算
- 投保限制 / 健康告知

### 7.3 优先需要视觉 Icon 的保险模块

- 核心卖点
- 适合谁 / 用户痛点
- 保障责任摘要
- 投保 / 理赔流程
- 服务权益 / 增值服务

但**不得为了“每块都有图”而机械堆 Icon**；当模块已经有明确插画或数据图时，不重复叠加装饰 Icon。

## 8. Insurance Illustration System

### 8.1 默认：轻量保险插画

用户未指定风格时优先使用：
- 白色 / 极浅蓝背景
- 蓝色主色 + 少量暖橙
- 半扁平 + 柔和渐变 / 轻 3D
- 轻阴影
- 简洁、专业、适合移动端

### 8.2 医疗场景插画

适用于住院、就医、药品、病床、院外购药等具体医疗语义。

规则：
- 一个主场景 + 1–3 个辅助元素。
- 不绘制复杂医院环境。
- 不强化病痛、恐惧、虚弱感。

### 8.3 信息插画

用于解释多项保障关系、配置逻辑或复杂机制。

- 中心主体：保单 / 保障卡 / 盾牌等。
- 外围信息节点建议不超过 3–4 个。
- 关系比装饰更重要。

### 8.4 选择规则

```text
基础操作 / 状态 → UI Icon
单一保险卖点 → 保险专业 Icon
模块解释 → 轻量保险插画
住院 / 就医场景 → 医疗场景插画
多项保障关系 → 信息插画
人群 / 服务 / 情绪主题 → 人物主视觉
```

## 9. Persona System

### 9.1 保险顾问

定位：**专业顾问 / 服务陪伴者，而不是强销售。**

#### 男顾问：许安
- 约 30 岁
- 温暖亲和、理性可靠、耐心细致
- 蓝色西装、浅色衬衫、小面积暖色点缀

#### 女顾问：林知暖
- 约 28 岁
- 知性亲和、细腻共情、专业沉稳
- 蓝色职业套装、工牌、平板

### 9.2 家庭人物

#### Family-3
年轻父母 + 1 名儿童。

#### Multi-generation
默认年轻父母 + 2 名儿童 + 2 位老人；根据用户内容可减少儿童数量，但保持“多代家庭保障”语义。

#### Senior
长辈 / 老年夫妻；表现健康、自然、整洁、亲和。

### 9.3 人物统一原则

- 轻 3D / 柔和 C4D。
- 蓝白主调 + 少量暖色服装。
- 自然互动、有陪伴感。
- 不低幼、不病弱、不过度摆拍。
- 页面内同一人物资产保持面部、发型、服装和比例稳定。

## 10. Insurance Data Visualization

通用数据可视化规则继承 `qieman-business-content-design`；本节只定义保险信息的推荐映射。

| 保险信息 | 推荐表达 |
|---|---|
| 等待期 / 投保 / 理赔流程 | 时间轴 / Step Flow |
| 院内 vs 院外 | 双栏对比 |
| 保障责任差异 | 对比卡 / 对比表 |
| 过去 vs 现在 | 双场景插画 + 对比信息 |
| 3–4 个产品优势 | 3 项卡片 / 2×2 卡片 |
| 保额 / 免赔额 / 保费 | 等权数字卡 + 简洁关系图 |
| 年龄 / 保障期限 | 区间轴 / 时间范围 |
| 保障组成 | 环图 / 分层结构 |
| 多阶段机制 | 时间线叙事 |

保险专项规则：
- 数据来源、统计口径、时间范围不得省略。
- 同一层级的金额、比例、期限等数据默认等权展示，不人为制造“一个超大、其余很小”的视觉主次。
- 不使用 K 线、交易屏、上涨箭头等投资类装饰。
- 演示数据与保证利益必须严格区分。

## 11. Content Protection & Insurance Safety

这是本 Skill 的最高优先级之一。

### 11.1 必须原样保护的保险事实

若用户提供标准文案 / 产品材料，以下内容不得擅自修改：
- 产品名称
- 保额 / 保费 / 免赔额 / 报销比例
- 等待期 / 保障期限 / 投保年龄
- 医院范围 / 药品范围
- 健康告知 / 免责条款 / 续保条件
- 保障责任 / 理赔条件
- 疾病名称 / 数量
- 服务范围
- 风险说明
- 数据来源 / 截止日期 / 统计口径

### 11.2 禁止行为

- 不新增用户未提供的保障责任。
- 不扩大承保范围。
- 不把“可能 / 符合条件可”改成“可以 / 一定”。
- 不把演示数据包装成保证结果。
- 不为了营销标题改变保险事实。
- 不弱化、隐藏免责、限制与重要说明。

### 11.3 缺失数据

必须占位时使用 `XX 万`、`XX 天`、`待确认` 等明显占位，不伪造真实感数字。

## 12. Insurance-specific Component Overrides

基础组件全部继承母 Skill，本节只定义保险场景中的语义约束。

### 12.1 Bottom CTA

吸底 CTA 的**视觉样式完全继承 `qieman-business-content-design`**：默认仅允许一个整行大按钮，占满安全区。

保险 Skill 不得因原型存在以下样式而覆盖母 Skill：
- 左右信息区 + 按钮
- 咨询 / 投保双按钮
- 两个半宽按钮
- 小胶囊按钮
- 多层固定栏

若业务确实需要两个动作，应优先把次级动作放回正文或以文本入口呈现；只有用户 / 业务明确要求双 CTA 时才例外。

### 12.2 Product Summary

保险首屏摘要优先呈现：
- 产品类型 / 核心保障
- 适合人群
- 关键投保门槛或限制

不得用纯营销 slogan 取代产品基本事实。

### 12.3 Disclosure / Important Notice

风险说明、免责、健康告知等可降低视觉强度，但不可降低信息可访问性；文字必须可读、可定位、不可隐藏在难发现的交互中。

## 13. Existing Design / Prototype Handling

原型处理的通用规则继承 `qieman-business-content-design`。

保险场景额外强调：
1. 不因视觉优化修改保障责任、产品事实、限制和数据。
2. 已有验证有效的保险模块可局部增强，不为了“重新设计”而破坏业务理解。
3. 用户明确要求保留原尺寸 / 原结构时，将其视为强约束。
4. “参考原型”不等于“照搬原型视觉”。
5. 保险 Hero、Icon、保障信息表达可重新设计，但必须服务于原业务逻辑。

---

## 14. Visual Avoidances

除非用户明确要求，否则避免：
- 满屏盾牌 / 爱心 / 医疗十字堆叠
- 大量医疗 Icon 装饰
- 低幼卡通 / 手绘线稿
- 高饱和糖果 3D / 强塑料玩具质感
- 复杂医院背景
- 现金、人民币、金币作为保险主视觉
- K 线、交易屏、上涨箭头等投资类语义
- 与保障内容无关的装饰性 3D 物件

**优先表达真实保险问题与保障场景，而不是抽象“保险感”。**

## 16. Final Audit Checklist

### A. 保险内容
- 产品事实是否与标准稿一致？
- 关键数字、期限、比例是否一致？
- 责任、限制、免责是否遗漏或被弱化？
- 是否生成了原文没有的保障能力？

### B. 信息表达
