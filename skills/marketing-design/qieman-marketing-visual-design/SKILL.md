# qieman-marketing-visual-design

## 1. Skill 定位

`qieman-marketing-visual-design` 是且慢业务页面的**营销视觉增强层**。

它主要解决：

- 页面已经有稳定内容结构，但 KV / Hero 不够有主题感；
- 页面头图视觉较弱，缺少营销氛围与视觉记忆点；
- 需要生成可用于 H5 / App 专题 / 活动页 / 策略页的无字背景图；
- 需要在不改变页面内容设计的前提下，提升整体视觉完成度；
- 需要根据业务主题生成更贴合语义的插画、场景图或视觉母题。

本 Skill **不负责重新设计页面结构**。

> 核心原则：**页面结构不动，视觉层增强。**

# 3. 非职责范围

以下内容默认**不得修改**：

- 原页面文案
- 标题
- 副标题
- 数据
- 规则
- 按钮文案
- CTA 样式
- 页面模块顺序
- 页面卡片结构
- 图表数据
- 风险提示
- 页面交互逻辑

除非用户明确要求，否则：

> **不得为了生成 KV 而重做整页。**

---

# 4. 默认输出原则

默认优先输出：

1. **无字 KV**
2. **无字 Hero 背景图**
3. **透明底前景插画**
4. **可直接嵌入页面的主视觉资产**

默认不直接把标题、按钮、营销文案画进图片。

原因：

- 页面文字由 HTML / UI 层控制；
- 避免字体变形与文字错误；
- 保持页面可编辑；
- 便于多端适配。

> 核心原则：**文字留给页面，图片负责视觉。**

- `#1B88EE`

辅助蓝：

- `#2679EE`
- `#2F7BEC`
- `#3A6BC9`

浅蓝：

- `#DDE5FF`
- `#E2E9FF`
- `#E7EFFD`
- `#F0F6FF`

- 橙
- 暖黄
- 少量浅粉
- 少量紫

# 10. 营销视觉强度

视觉营销强度分三级。

## Level 1｜内容型
适合：

- 投教
- 报告
- 专题
- 顾问内容

特点：

- 留白多
- 装饰少
- 信息感强
- 品牌感优先

---

## Level 2｜业务营销型

默认级别。

适合：

- 策略介绍
- 产品介绍
- 活动页
- 保险页

特点：

- 有明显主题
- 有核心视觉主体
- 有适度营销感
- 不做电商式强刺激

---

## Level 3｜活动型

适合：

- 优惠券
- 节日活动
- 限时活动
- 权益活动

特点：

- 视觉记忆点更强
- 可增加暖色
- 可增加节庆符号
- 仍保持且慢克制感

---

# 11. 构图系统

所有 KV 必须先确定**文字安全区**。

不要先生成完整画面，再想文字放哪里。

---

## 11.1 左侧大留白

适合：

- H5 Hero
- 策略页
- 营销活动页

结构：

```text
左 40%~55%
标题 / 副标题安全区

右 45%~60%
核心视觉主体
```

核心视觉主体不得进入标题主安全区。

---

## 11.2 右侧大留白

适合：

- 特殊页面布局
- 右侧排版
- 横向专题 Banner

---

## 11.3 中心留白

适合：

- 海报
- 大标题活动页

主体放在：

- 下方
- 四周
- 边缘

中间预留标题区。

---

## 11.4 上方留白

适合：

- 移动端长图
- 9:16
- 3:4

主体集中在中下区域。

---

# 12. 常用输出比例

支持：

- `16:9`
- `4:3`
- `3:4`
- `1:1`
- `9:16`

常见尺寸：

- `1125 × 576`
- `1125 × 750`
- `750 × ...`
- `1080 × 1920`
- `900 × 1200`
- `1100 × 1100`
- `375 × 812`

尺寸只是画布参数。

视觉主体、透视、比例不能因适配而拉伸。

# 13. 视觉生成方法

禁止：

> 直接把业务标题丢给模型自由发挥。

必须经过以下过程：

```text
业务语义
↓
提取关键词
↓
判断核心视觉隐喻
↓
选择视觉母题
↓
选择构图模板
↓
确定品牌配色
↓
确定禁用元素
↓
生成图片
```

# 14. 语义 → 视觉母题转换

## 14.1 稳健 / 长期

可考虑：

- 层叠结构
- 稳定基座
- 长线延展
- 平衡结构
- 缓慢生长
- 周期层
- 时间感

避免：

- 急速上涨箭头
- 暴涨柱状图
- 强交易感

---

## 14.2 多元配置

可考虑：

- 多区域拼接
- 多材质组合
- 模块拼合
- 多轨道
- 多层资产板块
- 中西元素融合

避免：

- 简单堆很多 icon
- 拼贴感过重
- 复杂地图

---

## 14.3 全球投资

可考虑：

- 跨区域连接
- 空间层级
- 全球视野
- 海内外元素的简化对应

避免：

- 巨型地球
- 地球仪
- 世界地图占据主体

---

## 14.4 红利 / 现金流

可考虑：

- 周期性流动
- 稳定输出
- 连续节点
- 时间序列
- 持续供给

避免：

- 金币雨
- 金元宝
- 大量现金
- 财神符号

---

## 14.5 活动 / 充值 / 权益

可考虑：

- 时间
- 日历
- 路径
- 节奏
- 轻量礼遇
- 可用权益
- 资金待机 / 收益继续

避免：

- 电商促销爆炸贴
- 夸张优惠券堆叠
- 巨型价格数字

---

## 14.6 保险 / 医疗

可考虑：

- 透明盾牌
- 医疗服务
- 家庭关系
- 医疗路径
- 保障层
- 安心空间

避免：

- 病弱人物
- 医院恐惧场景
- 过度医疗器械堆叠

---

# 15. AI 生图反同质化规则

金融生图最容易出现重复母题。

以下元素默认降低优先级：

- 道路
- 山峰
- 上涨箭头
- 城市
- 金币
- K 线
- 交易屏
- 柱状图
- 地球
- 圆环
- 放大镜
- 钻石
- 巨型玻璃装置

同一项目连续生成时：

> 不得连续两轮使用相同视觉母题。

---

# 16. 强禁用元素

默认禁止：

- 城市天际线
- 门
- 椅子
- 沙发
- 会议室
- 多人会议
- 会所空间
- K线
- 交易屏
- 大量金币
- 金元宝
- 低幼卡通
- 复杂桌面静物
- 过度玻璃装置
- 强奢侈品炫耀
- 夸张霓虹金融风

如用户明确要求某元素，可例外。

---

# 17. 简洁度规则

用户说“简洁”时，必须理解为：

- 1 个核心主体
- 0~3 个辅助元素
- 清晰留白
- 低视觉噪音
- 不用复杂背景填满
- 不用大量漂浮物
- 不用重复装饰

> 简洁 ≠ 什么都没有。  
> 简洁 = 一个明确视觉主题。

---

# 18. 背景图规则

背景图默认：

- 无文字
- 无按钮
- 无 Logo
- 不把整个页面画进去
- 不出现 UI 卡片
- 不生成完整 H5 截图
- 不生成假的数据模块

它只负责：

> Hero / KV 视觉背景。

---

# 19. 透明前景插画规则

当页面需要更强可控性时，优先生成：

> 透明底前景插画

而不是整张背景。

优点：

- HTML 可控制位置
- 可调大小
- 可适配多尺寸
- 可替换背景色
- 减少生成模型对版式的破坏

推荐结构：

```text
HTML / CSS 背景
+
透明 PNG 前景插画
+
HTML 标题文字
```

---

# 20. KV 视觉复杂度

推荐：

```text
70% 可控页面
30% AI 视觉资产
```

不要：

```text
100% AI 生成整页
```

AI 负责：

- 视觉主体
- 插画
- 背景
- 氛围

HTML / UI 负责：

- 文字
- 按钮
- 数据
- 卡片
- 排版

---

# 21. 主题准确度 Gate

生成前必须回答：

1. 这张图的业务主题是什么？
2. 用户第一眼能不能感受到主题？
3. 是否有明确金融 / 保险 / 活动语境？
4. 是否只是“漂亮但不相关”？
5. 视觉元素是否在服务文案？

如果主题识别弱：

> 不得仅靠标题解释图片。

---

# 22. 留白 Gate

必须检查：

- 标题区域是否安全
- 主体是否遮挡文案
- 视觉重点是否和文字抢焦点
- 移动端裁切后是否还能保持主体完整
- 画面边缘是否有高权重元素被裁断

---

# 23. 清晰度 Gate

必须保证：

- 主体清晰
- 边缘干净
- 透视正确
- 不变形
- 不出现多余手指 / 多余肢体
- 不出现错误几何结构
- 图标不糊
- 不使用水印
- 不出现乱码文字

---

# 24. 品牌一致性 Gate

检查：

- 蓝色是否接近且慢品牌体系
- 暖色是否控制
- 是否过饱和
- 是否过黑
- 是否过度奢华
- 是否低幼
- 是否像泛 AI 金融素材
- 是否具备且慢的宁静、可信赖与克制感

---

# 25. 视觉层级 Gate

一个 KV 只允许：

- 1 个一级视觉主体
- 1~2 个二级辅助视觉
- 少量背景层

不允许：

> 每个元素都在抢视觉中心。

---

# 26. 多方案生成规则

用户要求“多方案”时：

不要只变颜色。

每张应至少改变其中 2 项：

- 核心视觉母题
- 构图
- 主体元素
- 空间关系
- 视觉隐喻
- 风格强度

例如 4 张方案：

```text
A：时间隐喻
B：结构隐喻
C：场景隐喻
D：抽象金融隐喻
```

---

# 27. 参考图使用规则

参考图只用于提取：

- 风格
- 材质
- 构图
- 配色
- 光影
- 精致度

不得机械复制：

- 原图主体
- 原图业务符号
- 原图文字
- 原图品牌内容

如果用户说：

> “参考风格，不要改变构图”

则：

- 构图锁定
- 视觉风格转换
- 内容元素按用户要求替换

---

# 28. 已确认资产优先级

如果用户已经确认：

- 某人物
- 某 IP
- 某插画
- 某视觉主体

后续应：

> 基于已确认资产继续变体。

不得每轮重新生成完全不同的人物或主视觉。

---

# 29. IP 规则

如使用且慢 IP：

- 不改变人物比例
- 不改变核心识别
- 不随意更换服装与面部特征
- 动作变化可以
- 场景可以变化
- 输出时保持高清

涉及小顾等 IP 时，优先使用对应 IP Skill。

---

# 30. 金融表达规则

营销视觉可以有金融语义，但应克制。

推荐：

- 资产配置
- 时间
- 周期
- 分散
- 稳定
- 长期
- 收益连续性
- 组合结构

不推荐：

- 投机
- 暴涨
- 赌徒式收益
- 满屏红绿
- K线交易
- 财富炫耀

---

# 31. 保险表达规则

保险视觉的目标是：

> 专业、安心、可靠、有人协助。

推荐：

- 蓝白
- 少量暖橙
- 轻 3D
- 柔光
- 医疗符号
- 家庭守护
- 服务路径

避免：

- 病患痛苦
- 重症恐惧
- 医疗恐吓
- 全蓝医疗器械堆叠

---

# 32. 营销文案与视觉关系

视觉必须回应：

- 标题主题
- 核心利益点
- 用户场景

例如：

```text
标题：好时光，小收益
视觉：
时间 + 连续收益节点
```

而不是：

```text
标题：好时光，小收益
视觉：
随机金币 + 城市 + 上涨箭头
```

---

# 33. Hero 不得“替页面做 UI”

禁止在生图里出现：

- 卡片
- 按钮
- 表格
- 图表
- 导航
- 底部 CTA
- 手机 UI
- H5 页面截图

除非用户明确要求制作 UI Mockup。

---

# 34. 输出形式

默认：

- PNG
- 高清
- 无字

需要时：

- 透明 PNG
- 纯白背景
- 指定背景色
- 多尺寸适配

---

# 35. 推荐输出数量

默认：

- 单次 4 张方案

若用户指定：

- 1 张
- 2 张
- 3 张
- 4 张

则严格按数量执行。

# 36. 页面视觉增强模式

当用户提供完整页面 HTML / 截图，并说：

> “页面不动，只优化 KV”

则执行：

```text
锁定页面结构
锁定文案
锁定卡片
锁定图表
锁定 CTA
↓
只提取 Hero 视觉区域
↓
分析主题
↓
生成 KV 资产
```

不得重新生成页面。

# 36.1 Hero / KV 与正文衔接规则

当页面顶部存在 Hero / KV，且下方进入正文内容区时，默认执行**圆角衔接**，作为固定视觉规范。

## 默认规则

- **KV / Hero 下方的正文内容容器顶部必须使用圆角衔接**
- 默认圆角值：**20px（1倍图）**
- 正文内容区可以轻微上移，与 Hero 形成自然覆盖衔接
- 衔接处应使用**整块内容容器**完成过渡，不是单独画一条装饰弧线
- 圆角只作用于**正文内容容器顶部**，下方内容模块结构不因此被改变

## 目的

这样做是为了：

- 让 KV 与正文过渡更自然
- 保持已验证过的且慢页面风格一致性
- 避免 Hero 结束后直接“硬切”到正文内容
- 强化页面整体完成度与精致感

## 配色关系

- 页面背景色仍遵循主页面规范
- 正文区的容器底色与页面背景保持一致
- 白卡继续按照内容设计规则铺设，不因圆角衔接而改成大面积分色块

## 禁止情况

禁止出现以下做法：

- Hero 与正文之间直接硬切，没有圆角过渡
- 圆角做成很夸张的拱形或波浪形
- 圆角过渡区域颜色与正文主背景不一致
- 圆角过渡只做局部，不形成完整容器关系

> 这是一条固定规则：**只要页面是“顶部 KV / Hero + 下方正文”结构，就优先使用正文顶部圆角衔接。**


# 37. 页面联动模式

当新 KV 生成后，如果用户要求替换进 HTML：

允许调整：

- Hero background-image
- 前景图尺寸
- 前景图位置
- Hero 最小高度
- Hero 与正文之间的圆角衔接容器
- 标题安全区

不允许调整：

- 下方模块结构
- 数据
- 卡片
- 图表
- CTA
- 文案

# 38. 版本稳定性

用户确认某 KV：

> “这个方向可以”

则该版本成为：

`Locked Visual Direction`

后续修改：

- 只改用户指出部分
- 不随机切换母题
- 不重做全部构图
- 不改变已确认风格

---

# 39. Visual Regression Gate

每轮修改后检查：

- 主视觉是否仍为同一方向
- 色调是否漂移
- 主体是否变形
- 留白是否丢失
- 是否新增无关元素
- 是否重新出现禁用元素
- 是否改变用户确认的比例与构图

# 45. 固定原则总结

本 Skill 的核心不是：

> “生成一张好看的图”

而是：

> **生成一张能真正进入且慢业务页面、可被 HTML 使用、主题准确、构图可控、品牌一致的营销视觉资产。**

执行优先级：

```text
业务语义准确
>
页面可用性
>
留白与构图
>
品牌一致性
>
视觉精致度
>
装饰感
```

# 46. 最终硬规则

1. 页面结构默认不改。
2. 页面文案默认不改。
3. KV 默认无字。
4. 不生成完整页面截图。
5. 不让 AI 同时决定页面结构和视觉。
6. 先定视觉母题，再生图。
7. 一张图只保留一个主视觉中心。
8. 默认保留明确文字安全区。
9. 禁止泛金融 AI 套路化元素重复使用。
10. 已确认视觉方向不得随机重构。
11. 视觉增强不能破坏 `qieman-business-content-design` 已稳定的页面布局。
12. 顶部 Hero / KV 与正文内容之间默认使用 **20px 顶部圆角衔接**。
13. 需要数据图表时交给 `qieman-chart-design`，本 Skill 不负责图表设计。
14. 需要页面基础组件时遵循 `qieman-ui-design`。
15. 需要垂类人物 / IP / 保险定制资产时按需叠加对应 Skill。
