# Visual Maturity Engine｜视觉成熟度增强引擎

`qieman-marketing-visual-design` 的核心职责不是单纯“生成 Hero / KV”，
而是把一个业务正确、框架正确的页面，提升到**成熟设计稿**的视觉水平。

它是：

> **Visual Maturity Layer｜视觉成熟度增强层**

默认服务对象：

- `qieman-business-content-design`
- 已确认业务 HTML
- 市场 / 顾问 / 内容 / 产品运营 / 保险 / VIP / AI 等业务页面
- Hero / KV / Background / Illustration / 页面整体视觉方向

它不替代主 Skill，不重新定义业务结构。

---

## 1. 与主 Skill 的职责边界

### `qieman-business-content-design`
负责：

- Content Lock
- Framework Contract
- 模块数量与顺序
- 业务关系
- 页面 IA
- CTA / Interaction
- Risk / Compliance
- HTML 最终实现

### `qieman-marketing-visual-design`
负责：

- 页面视觉概念
- Hero / KV 构图
- 核心视觉主体
- 页面背景关系
- Hero → 正文视觉承接
- 文字安全区
- KPI 安全区
- CTA 安全区
- Icon / Illustration 风格
- 色彩 / 材质 / 光影
- 页面视觉密度
- 品牌感
- 反 AI 同质化
- 视觉成熟度验收

核心：

> **主 Skill 负责“别把业务做错”；本 Skill 负责“别把视觉做得像 AI 初稿”。**

---

## 2. HTML-First Default｜默认面向 HTML 实现

用户发截图、参考图、设计稿，默认理解为：

> **用于指导当前 HTML 的视觉方向。**

除非用户明确要求：

- 生成图片
- 生成插画
- 生成图标
- 生成参考图
- 输出独立视觉资产

否则：

```text
视觉方向
↓
HTML / CSS / SVG 可实现表达
↓
由 qieman-business-content-design 输出完整 HTML
```

禁止因为看到参考图就默认转成图片生成任务。

# Visual Craft & Refinement Gate｜视觉工艺与精致度

本 Gate 用于约束所有业务页面的“完成度”，不针对某一种页面类型，也不绑定固定视觉元素。

核心原则：

> **成熟设计不是元素更多，而是留下来的每一个元素都必要、精致、协调。**

不论页面来自市场、顾问、内容、策略、产品、保险、VIP、AI / 开放平台、活动、报告 / 诊断，都必须检查以下 8 个维度：

```text
Hierarchy        主次
Proportion       比例
Density          密度
Material         材质
Lighting         光影
Color Depth      色彩层次
Detail Quality   细节完成度
Restraint        克制
```

## 1. Hierarchy｜主次

同一屏必须有清晰视觉层级：

```text
第一层：页面主题 / 核心利益
第二层：主视觉 / 核心数据
第三层：辅助说明
第四层：装饰
```

规则：
- 同一屏最多只能有一个第一视觉中心；
- 辅助元素必须主动降权；
- 不允许标题、数字、插画、标签、图标、光圈同时抢第一层级；
- 视觉主体不能压过业务主题；
- 装饰不能压过信息。

若用户无法在 1 秒内判断“这一屏最重要的是什么”：

> **Hierarchy Failed**

## 2. Proportion｜比例

视觉成熟度优先检查比例关系，而不是单个元素是否好看。

必须检查：
- 主视觉相对 Hero 的占比；
- 标题区与视觉区比例；
- 主体与辅助元素比例；
- 卡片高度与内容密度；
- 标题 / 正文 / 数据之间的视觉重量；
- 留白相对于内容量是否合理。

禁止：
- 主视觉过大，挤压文案；
- 主视觉过小，像装饰；
- 卡片过高但信息很少；
- 为了塞图而压缩文字安全区；
- 通过缩字号解决空间不足。

原则：

> **先调比例，再调细节。**

## 3. Density｜密度

简洁不等于元素数量固定，而是没有冗余。

判断每个元素：
1. 是否有业务作用？
2. 是否有视觉作用？
3. 删除后表达是否变差？
4. 是否与其它元素重复表达？

若删除后主题更清楚、构图更稳定、信息不受损，则该元素应被删除。

核心：

> **设计密度来自信息需要，不来自“画面要丰富”。**

## 4. Material｜材质

同一页面必须有统一工艺语言。

可采用：
- 扁平；
- 半扁平；
- 轻 3D；
- 半拟物；
- 透明 / 磨砂；
- 纸张感；
- 金属感；
- 纯信息图形。

但不能在同一页面中无理由混用扁平 icon、高光 C4D、卡通人物、玻璃球、金属按钮等不同材质体系。

规则：
- Hero 与正文 icon / illustration 应可共存；
- 同组 icon 材质统一；
- 阴影、倒角、透明度有一致逻辑；
- 材质必须服务业务气质，不是为了“高级”。

若页面看起来像多个素材库拼接：

> **Material Consistency Failed**

## 5. Lighting｜光影

光影用于建立空间，不用于制造噪声。

必须：
- 主光方向一致；
- 阴影强度分级；
- 主体阴影 > 辅助元素阴影；
- 背景光效不抢正文；
- 高光集中在必要位置。

禁止：
- 每个元素都发光；
- 每个卡片都有重阴影；
- 多个不同方向的光源；
- 大面积炫光掩盖文字；
- 为了“科技感”滥用辉光。

核心：

> **光影应该让结构更清楚，而不是让画面更复杂。**

## 6. Color Depth｜色彩层次

颜色设计必须有：

```text
主色域
↓
明度层次
↓
辅助色
↓
强调色
```

要求：
- 品牌色负责统一；
- 强调色只用于真正重要信息；
- 同一屏避免多个高饱和色平均分配；
- 背景、卡片、内容层必须有明确明度差；
- 金融语义色不得与装饰色混用。

成熟感来自深浅关系、冷暖关系、饱和度控制、色彩面积比例，而不是“用了某个高级色”。

## 7. Detail Quality｜细节完成度

细节不是增加装饰，而是提高已存在元素的完成度。

可优化：
- 边缘高光；
- 微弱倒角；
- 透明边界；
- 轻纹理；
- 刻度；
- 局部结构线；
- 阴影软硬；
- 内外间距；
- 对齐；
- 圆角过渡；
- 图标线宽。

要求：
- 细节必须在正常手机尺寸下仍有价值；
- 不出现只在放大截图里才看得到的无效细节；
- 不为了“精致”堆小点、小线、小光圈。

核心：

> **少量元素 + 更高完成度，而不是更多元素 + 更高复杂度。**

## 8. Restraint｜克制

成熟设计必须主动做减法。

默认不应：
- 所有模块都有阴影；
- 所有标题都有 icon；
- 所有数字都有强调色；
- 所有内容都装进卡片；
- 所有 Hero 都有复杂主视觉；
- 所有模块都加装饰背景；
- 所有地方都做渐变。

判断：

> 如果某个设计元素存在的唯一理由是“这里空了”，默认不应加入。

核心：

> **设计感不是可见设计元素的数量，而是信息、比例、色彩、材质和留白被控制得恰到好处。**

# Visual Redundancy Gate｜视觉冗余检查

交付前逐一检查主视觉、辅助图形、icon、装饰、光效：

- [ ] 是否有重复语义？
- [ ] 是否有纯填空元素？
- [ ] 是否出现两个以上同权重视觉中心？
- [ ] 是否存在删除后反而更清晰的元素？
- [ ] 是否为了“丰富”而牺牲留白？

如果存在明显冗余：

> **Visual Redundancy Failed**

# Craft Quality QA｜视觉工艺验收

交付前必须检查：

- [ ] Hierarchy：第一视觉中心是否唯一？
- [ ] Proportion：文字区和视觉区比例是否合理？
- [ ] Density：是否没有冗余元素？
- [ ] Material：材质语言是否统一？
- [ ] Lighting：光源和阴影是否克制一致？
- [ ] Color Depth：主色、辅助色、强调色是否有层级？
- [ ] Detail Quality：细节是否提高完成度，而不是增加噪声？
- [ ] Restraint：是否主动做了减法？

若 8 个维度中有 2 个以上明显失败：

> **Visual Craft Gate Failed**

不得视为成熟设计稿。

# Generalization Rule｜通用化原则

本 Skill 不应固化：

- 某个产品一定使用某种元素；
- 某种页面必须使用固定构图；
- 某个业务必须固定元素数量；
- 某种营销页必须使用固定配色。

应固化的是：

- 视觉主次；
- 比例；
- 密度；
- 材质一致性；
- 光影；
- 色彩层次；
- 细节完成度；
- 克制。

即：

> **固定的是设计判断标准，不是视觉模板。**


# Hero Clarity Gate｜KV 清晰度与主题聚焦

本 Gate 专门解决以下常见问题：

- 背景过浅，首屏没有视觉聚焦；
- 白字落在浅底上，标题可读性不足；
- 右侧图标 / SVG / 小物件过多；
- 主视觉没有明确中心；
- 元素虽然“相关”，但主题识别仍然模糊；
- KV 像素材拼贴，而不是成熟营销主视觉。

核心原则：

> **KV 第一眼必须先看懂主题，再感受到氛围，最后才是装饰。**

## 1. Background Strength｜背景必须有足够视觉承载力

营销 / 活动 / 充值 / 引导类 KV，背景不能过灰、过淡、过弱。

必须判断：

- 背景能否承载标题；
- 主视觉是否从背景中清晰分离；
- Hero 是否和正文形成明确但自然的层级；
- 首屏是否有“活动页 / 营销页”的第一眼聚焦。

### 禁止

- 大面积接近白色的灰蓝底承载白色标题；
- 背景与正文几乎同色，导致 KV 没有起势；
- 只有一层平淡浅色渐变；
- 为了“高级”而把整体对比度压得过低。

### 推荐

可根据主题选择：

- 品牌蓝 / 蓝紫的中等明度渐变；
- 暖粉 / 暖橙的节日活动渐变；
- 蓝 + 暖色的冷暖过渡；
- 深浅分区 + 柔和高光；
- 有明确视觉中心的局部光晕。

核心：

> **背景必须服务文字可读性和主视觉识别，不是单纯做“浅色高级感”。**

## 2. Text Contrast Gate｜标题对比度强制规则

标题颜色必须由背景亮度决定。

### 浅背景
优先：
- 深蓝；
- 深灰蓝；
- 品牌深色；
- 暖深色强调。

### 中深背景
可以使用：
- 白色；
- 暖白；
- 高亮暖色关键词。

### 禁止

- 白字 + 浅蓝 / 浅粉 / 浅灰底；
- 浅灰字 + 浅色背景；
- 标题和背景只靠轻阴影区分；
- 同一句标题里出现 3 种以上高饱和颜色。

如果主标题需要依赖“仔细看”才能读清：

> **Text Contrast Failed**

## 3. Dominant Visual Hierarchy｜主视觉主次

KV 必须存在清晰的视觉主次，但**不得把元素数量写成固定模板**。

判断顺序：

```text
业务主题
↓
第一视觉中心
↓
必要的辅助关系
↓
背景氛围
```

规则：

- 同一屏必须能明确识别第一视觉中心；
- 辅助元素只在有业务表达、空间组织或视觉平衡价值时保留；
- 不要求固定“1 个主体 + N 个辅助元素”；
- 删除某元素后，如果主题更清楚、比例更稳定、信息不受损，则该元素应删除；
- 多元素场景可以成立，但必须有明显权重差；
- 单元素场景也可以成立，但必须有足够的构图、材质、光影和细节完成度；
- 不通过堆叠图标、装饰物、漂浮物来制造“丰富感”。

核心：

> **固定的是主次关系，不是元素数量。**

若第一眼看到的是“很多元素”，而不是业务主题：

> **Dominant Visual Hierarchy Failed**

## 4. Theme Focus｜主题必须明确

KV 必须能用一句话描述其视觉主题。

例如：

```text
“双节期间，提前充值，用时间换取连续收益”
```

若视觉无法用一句清晰业务语义概括，而只能描述成：

```text
“蓝色背景 + 时钟 + 卡片 + 一些图标”
```

则主题建立失败。

### Theme Check

Hero 完成后必须回答：

1. 核心主题是什么？
2. 主视觉为什么能表达这个主题？
3. 每个辅助元素为什么存在？
4. 删除其中任意一个元素后，是否反而更清楚？

如果第 4 题经常答案为“是”，说明元素过多。

## 5. Visual Hierarchy｜首屏视觉层级

推荐层级：

```text
主标题
↓
核心利益点
↓
核心主视觉
↓
辅助说明 / 标签
```

或：

```text
左侧标题 + 核心利益
右侧 1 个主视觉
```

禁止：

- 标题、标签、主视觉、KPI、装饰同时抢第一视觉层级；
- 右侧主视觉由多个同等大小对象构成；
- 主视觉比业务利益点更抢；
- 首屏存在 3 个以上“视觉中心”。

## 6. Theme-driven Color｜活动配色必须服务主题

对于节日 / 活动类页面：

### 蓝色方向
适合：
- 更金融；
- 更稳健；
- 更通用；
- 品牌一致性更强。

要求：
- 背景蓝必须有足够深浅层次；
- 文字对比度必须通过；
- 暖色只强调“收益 / 时间 / 权益”。

### 暖色方向
适合：
- 双节；
- 福利；
- 节庆；
- 权益活动。

要求：
- 不能做成电商大促红；
- 正文仍保持克制；
- 品牌蓝继续承担功能 / CTA / 交互识别。

## 7. Activity KV Composition｜活动页推荐构图

推荐：

```text
左侧 55–62%：标题 + 核心利益点
右侧 38–45%：1 个主视觉主体
```

主视觉不能迫使标题区过窄。

若标题因右侧视觉导致：
- 过度折行；
- 3–4 行碎裂；
- 关键词被拆开；

则优先：
- 缩小主视觉；
- 增加 Hero 高度；
- 调整左右比例；

而不是缩字。

## 8. Hero Visual Simplification QA｜KV 减法验收

交付前检查：

- [ ] 背景是否有足够承载力？
- [ ] 标题与背景对比是否清楚？
- [ ] 第一视觉中心是否明确？
- [ ] 辅助元素是否全部必要？
- [ ] 每个元素是否都和主题、构图或空间关系有关？
- [ ] 删除冗余元素后是否更清晰？
- [ ] 首屏是否能一句话说清视觉主题？
- [ ] 是否没有“图标拼贴感 / 素材库拼接感”？
- [ ] 375px 下标题是否自然换行？
- [ ] KV 是否能明显定义整页视觉基调？

若出现：

```text
背景过浅
文字对比不足
视觉中心分散
装饰冗余
素材拼贴
主题不明确
```

则：

> **Hero Visual Simplification Failed**


# Visual Typography Gate｜视觉排版强制验收

视觉成熟度首先取决于排版稳定性。任何页面在进入“完成”状态前，必须先通过 Typography Gate。

核心原则：

> **先保证文字层级、宽度、换行和对齐稳定，再谈装饰和视觉氛围。**

## 1. Default Type Scale｜默认字号层级

若上游 Figma / Sketch / 已确认设计规范没有明确覆盖，默认采用：

| 层级 | 默认值 |
|---|---|
| KV / Hero 主标题 | 30px / Medium / 120% |
| 一级模块标题 | 20px / Medium / 140% |
| 卡片标题 | 16px / Medium / 140% |
| 核心正文 | 14px / Regular / 160% |
| 辅助正文 | 12px / Regular / 160% |
| 标签 / 辅助状态 | 10–11px |
| Sticky CTA | 17px / 25px / Regular |

规则：

- 同级信息字号必须一致；
- 同级 KPI 数字必须等权；
- 不因文字长短随机缩字号；
- 不为了“塞进去”把 14px 正文压成 10–11px；
- 需要更多空间时，优先增加高度 / 换行 / 重排，而不是缩字。

## 2. Text Width & Wrap｜文本宽度与换行

移动端 375px 下必须检查：

- 主标题是否按语义自然换行；
- 标题是否因容器过窄出现 3–4 行碎裂；
- 数字 / 单位是否被拆开；
- “14天 / 15:00 / 9月23日”等关键信息是否被无意义折行；
- 标签是否因宽度不足变成两行胶囊；
- 卡片标题是否出现大小不一或基线不齐。

禁止：

```text
为了给右侧视觉让位置
→ 把标题压成极窄列
→ 造成连续折行
```

应优先：

```text
重新调整 Hero 文案区 / 视觉区比例
或
增加 Hero 高度
或
降低视觉主体占宽
```

## 3. Numeric Hierarchy｜数字层级

关键数字必须遵循：

- 同组 KPI 同字号、同字重、同基线；
- 正收益 / 利益点可用暖色突出；
- 不允许因为位数不同而改变字号；
- 单位与数值保持合理绑定；
- “0元 / 1折起 / 自动匹配”等并列信息视觉权重一致。

## 4. 375px Typography QA

至少验证：

- 320 / 360 / 375 / 390 / 414；
- 标题不重叠；
- 正文不出现单字竖排；
- 不出现孤立标点；
- 不出现 KPI 溢出；
- 不出现按钮文字折行；
- 不出现标签高度不一致。

若存在明显折行、字号漂移、同级信息不等权：

> **Typography Gate Failed**

---

# Hero Asset Quality Gate｜KV 主视觉资产质量门槛

KV / Hero 的主视觉质量不能用“能画出来”代替“设计成熟”。

核心原则：

> **SVG 可实现，不代表 SVG 适合承担品牌级 KV 主视觉。**

## 1. Asset Routing｜视觉资产路由

在确定 Visual Concept 后，必须判断主视觉应该由哪种资产承担。

### A. HTML / CSS / SVG 适合

用于：

- 简单几何背景；
- 信息结构；
- 流程 / 关系 Diagram；
- 数据关系；
- 小型功能 icon；
- 低权重装饰；
- 简单品牌辅助图形。

### B. 高质量独立视觉资产适合

当 KV 需要以下能力时，应优先使用高质量插画 / 轻 3D / 半拟物视觉资产，而不是程序化拼 SVG：

- 体积感；
- 材质；
- 柔和光影；
- 真实空间层次；
- 人物；
- 家庭；
- 高端产品视觉；
- 节日营销主视觉；
- 品牌级 Hero 主体。

最终交付仍然是 HTML；独立视觉资产应作为 HTML 中的视觉资源使用，而不是把整页输出变成图片。

## 2. No Placeholder SVG｜禁止占位式 SVG

以下情况不得作为 KV 核心主体：

- 几个圆 + 几条线拼出的“时钟”；
- 一个空白方块；
- 通用圆环；
- 通用盾牌；
- 无语义玻璃块；
- 看起来像系统 icon 放大版；
- 只为了填满右侧空间的几何体。

若视觉主体给人的感觉是：

```text
功能图标
占位图
程序化示意图
```

而不是：

```text
成熟营销主视觉
```

则：

> **Hero Asset Quality Failed**

## 3. Mature Asset Style｜成熟视觉资产标准

推荐：

- 轻 3D / 半拟物；
- 透明或半透明材质；
- 柔和高光；
- 低饱和渐变；
- 软阴影；
- 清晰体块；
- 少量暖色强调；
- 简洁、克制、高清。

禁止：

- Q版；
- 卡通贴纸；
- 糖果色；
- 过度圆润软萌；
- 低幼人物；
- 粗糙渐变；
- 图标放大冒充 KV；
- 同时堆叠过多小物件。

## 4. Theme Match｜主题匹配

KV 主视觉资产必须同时通过：

1. **Theme Relevance**：与业务主题直接相关；
2. **Visual Maturity**：达到成熟设计稿水平；
3. **Brand Compatibility**：能与且慢品牌视觉共存；
4. **Page Continuity**：正文能延续其色彩 / 材质 / 氛围；
5. **Mobile Readability**：375px 下仍然清楚。

只满足“相关”，但视觉低幼：不通过。  
只满足“好看”，但与主题无关：不通过。

## 5. No-Text Asset Rule｜主视觉资产默认无字

独立 KV 视觉资产默认：

- 不内嵌标题；
- 不内嵌按钮；
- 不内嵌营销文案；
- 不内嵌复杂 UI 文本。

页面文字应由 HTML 承担。

---

# Visual Quality Priority｜视觉质量优先级

当存在冲突时：

```text
可读性 / Typography
>
业务准确性
>
KV 主题识别
>
主视觉质量
>
装饰丰富度
```

禁止为了“更有视觉感”牺牲：

- 字号稳定；
- 文字可读；
- KPI 对齐；
- 业务信息；
- 移动端空间。

---

# Confirmed Mature Reference Direction｜已确认成熟参考方向

对于营销活动类页面，成熟设计通常表现为：

- KV 有明确主题，但元素数量克制；
- 主视觉有材质 / 光影 / 空间层次，而不是 icon 拼贴；
- 主标题和核心利益点稳定可读；
- 暖色用于利益点 / 节日气氛；
- 正文收回到浅色背景 + 统一白卡；
- 模块内部表达各异，但外层系统一致；
- 视觉吸引力来自主题、构图和质感，不来自堆元素。

若生成结果相比已确认设计方向明显：

- 更低幼；
- 更碎；
- 字体更乱；
- KV 更像示意图；

则视为：

> **Visual Maturity Regression**


# Mature Marketing Visual Calibration｜成熟营销视觉校准

本节基于已完成的真实营销页面设计样本沉淀，用于校准市场 / 顾问 / 内容等业务页面的视觉成熟度。

目标不是把页面“做得更花”，而是：

> **在业务内容、框架、模块顺序不变的前提下，围绕页面主题重新建立成熟、统一、可信赖且有吸引力的视觉语言。**

---

## 1. Theme-First KV｜KV 主题先行

KV / Hero 不从“要放什么元素”开始，而从“这页核心业务主题是什么”开始。

必须先抽取：

```text
业务主题
↓
页面目标
↓
核心利益点 / 核心认知
↓
视觉母题
↓
主视觉元素
```

例如充值活动页，若核心主题是：

- 双节
- 提前充值
- 时间窗口
- 连续收益
- 支付抵扣券

则 KV 应围绕“时间收益 / 节日收益 / 提前准备”建立视觉母题。

可选元素可以包括：

- 时间装置
- 日历
- 关键日期节点
- 连续收益标记
- 权益券

但禁止把这些元素机械拼贴成“功能图标集合”。

核心：

> **主题驱动元素选择，而不是元素驱动设计。**

---

## 2. Mature Element Style｜元素成熟度

营销页的视觉元素应具备：

- 专业；
- 克制；
- 轻营销感；
- 品牌可信赖感；
- 移动端识别清晰。

### 推荐方向

- 轻 3D / 半拟物；
- 轻玻璃 / 半透明材质；
- 柔和高光；
- 低噪点；
- 简洁几何；
- 金融信息图形化；
- 结构明确的主体；
- 适量暖色作为利益点强调。

### 禁止低幼化

默认禁止：

- Q 版卡通；
- 过度圆润软萌；
- 儿童插画感；
- 大量 emoji / 表情；
- 糖果色堆叠；
- 贴纸式装饰；
- 过量小元素；
- 主体拟人化过强；
- 为了“活泼”牺牲专业感。

若视觉给人的第一印象是：

```text
可爱 > 专业
装饰 > 主题
元素多 > 信息清楚
```

则视为：

> **Mature Visual Failed**

---

## 3. Color by Theme｜配色按主题路由

不能默认“所有金融页面 = 一套品牌蓝”。

正确逻辑：

```text
业务主题
↓
情绪基调
↓
主色
↓
辅助色
↓
利益点强调色
```

### 默认品牌蓝模式
适合：

- 稳健理财；
- 投顾产品；
- 策略介绍；
- 通用金融营销；
- 专业服务。

特点：

- 品牌蓝 / 浅蓝为基底；
- 白色卡片；
- 暖色只做关键利益点强调。

### 节日 / 活动暖色模式
适合：

- 节日充值；
- 福利活动；
- 双节活动；
- 权益营销。

允许：

- KV 使用暖粉 / 暖橙建立节日氛围；
- 正文仍保持浅底 + 白卡，保证金融专业度；
- 品牌蓝继续承担按钮、功能、交互、信息识别。

禁止：

- 高饱和电商红；
- 大面积促销色堆叠；
- 全页暖色导致金融可信赖感下降。

### 其它主题模式
可根据业务语义选择：

- 蓝 + 金橙：价值 / 权益；
- 蓝 + 浅紫：内容 / 投教 / 认知；
- 蓝白 + 暖橙：保险 / 家庭 / 服务。

核心：

> **颜色为主题服务，品牌色负责统一，而不是机械占满页面。**

---

## 4. KV → Body Semantic Continuity｜KV 与正文语义连续

KV 的主题表达必须在正文继续出现。

例如 KV 使用“时间收益”作为主视觉母题：

正文模块应优先用：

- 收益日历；
- 时间节点；
- 阶段收益；
- 自动生效；
- 权益领取；

等表达方式继续承接。

禁止：

```text
KV 讲时间收益
正文突然换成无关的抽象科技风
```

或：

```text
KV 是暖节日感
正文全部变成冷科技卡片
```

核心：

> **Hero 是整页视觉系统的起点，正文是主题语言的延续。**

---

## 5. Card System｜统一外层，内部多样

正文外层系统应保持统一：

- 白卡背景；
- 圆角一致；
- Shadow 强度一致；
- 内边距一致；
- 标题体系一致；
- 模块间距一致。

但模块内部必须根据内容自由设计：

- 日历；
- 对比；
- Timeline；
- UI 指引；
- 权益说明；
- 产品信息；
- 图表；
- 人物提示；
- 流程 Diagram。

禁止：

> 所有模块都变成“同一张白卡 + 三行文字”。

核心：

> **外层系统统一，内部表达多样。**

---

## 6. Character Usage｜人物只做辅助

营销页可以使用人物，但人物默认属于辅助视觉，不承担整页主视觉。

适合：

- 关键提醒；
- 操作说明；
- 顾问提示；
- 陪伴感；
- 局部情绪强化。

要求：

- 人物尺寸克制；
- 不抢产品信息；
- 不过度卡通化；
- 不连续多个模块反复使用人物；
- 人物风格必须与 KV 材质、光影、配色兼容。

保险页可根据 `qieman-insurance-design` 使用家庭 / 顾问人物作为更重要视觉资产。

---

## 7. Marketing Rhythm｜营销转化节奏

在 Framework Contract 已锁定的前提下，不得擅自调整模块顺序。

但视觉层级应帮助用户按转化逻辑阅读：

```text
第一眼：为什么值得关注
↓
第二步：核心利益 / 关键结论
↓
第三步：怎么参与 / 怎么操作
↓
第四步：权益 / 产品补充
↓
最后：CTA 与合规
```

通过以下方式建立转化节奏：

- KV 强化核心利益点；
- 关键数字使用暖色 / 大字号；
- 操作步骤降低理解成本；
- 产品信息在靠后区域完成信任承接；
- CTA 明确且唯一；
- 风险提示保持克制但完整。

注意：

> **营销节奏通过视觉层级实现，不通过擅自重排 Framework 实现。**

---

## 8. Illustration Density｜视觉元素密度

移动端营销页不使用固定元素数量配额，而使用 **必要性 + 主次 + 移动端识别度** 判断密度。

每个视觉元素必须至少满足一项：

- 承担业务语义；
- 建立第一视觉中心；
- 建立必要空间关系；
- 提供必要的品牌 / 氛围识别；
- 改善构图平衡。

如果元素只承担“填空”“让画面更丰富”“增加一点设计感”，默认删除。

在 375px 下必须满足：

- 第一视觉中心仍清楚；
- 辅助元素不会缩成噪点；
- 标题安全区完整；
- 不出现多个同权重视觉焦点；
- 留白仍可感知。

核心：

> **视觉密度由信息和构图决定，不由元素数量决定。**


---

## 9. Business Theme Visual Check｜主题视觉检查

每个核心视觉元素必须同时通过：

### Theme Relevance
是否和当前业务主题直接相关？

### Information Value
是否帮助理解核心利益 / 页面主题？

### Maturity
是否符合金融品牌的成熟度？

### System Compatibility
是否能与页面正文视觉系统共存？

如果元素仅满足“好看”，但不满足业务主题，则不得采用。

---

## 10. Mature Marketing QA｜成熟营销页面验收

交付前检查：

- [ ] KV 是否围绕业务主题建立，而不是元素拼贴？
- [ ] KV 是否没有沿用需求原型旧视觉资产？
- [ ] 主视觉是否成熟、克制、不低幼？
- [ ] 主色 / 辅色 / 强调色是否由主题推导？
- [ ] 暖色是否用于利益点 / 节日氛围，而不是无目的铺满？
- [ ] KV 与正文是否保持同一视觉语言？
- [ ] 同级卡片是否统一？
- [ ] 模块内部是否根据内容采用不同表达？
- [ ] 人物是否只在需要时辅助表达？
- [ ] 页面是否形成明确的利益点 → 操作 → 产品 → CTA 节奏？
- [ ] 375px 下是否仍然清晰？
- [ ] 是否达到“可进入设计评审”的成熟度？

若视觉结果出现：

```text
原型换皮
低幼卡通
元素堆砌
配色失控
KV 与正文割裂
```

则：

> **Marketing Visual Calibration Failed**


# KV / Hero Visual Rebuild｜首屏视觉重建

当用户要求“重新设计页面视觉”“视觉重做”“不沿用原型表现”时，
KV / Hero 必须视为**视觉重建设计任务**，不是旧资产复用任务。

核心原则：

> **KV 决定整个项目的视觉基调。**

KV / Hero 的以下内容必须基于当前页面主题重新建立：

- Hero 背景氛围；
- 核心视觉主体；
- 插画 / SVG / Diagram；
- 主色 / 辅色 / 点缀色关系；
- 光影 / 材质 / 空间层次；
- 文字安全区；
- KPI / CTA / Transition 安全区。

除非用户明确要求：

- 沿用当前 Hero；
- 保留现有头图；
- 只优化局部；
- 基于当前视觉继续。

否则默认：

> **不得直接沿用需求原型中的旧 KV 图、旧 SVG、旧插画、旧主题配色和旧视觉母题。**

---

## KV Visual Isolation Gate｜KV 视觉隔离

需求 HTML / 原型中的 KV 默认只作为：

- 主题来源；
- 文案来源；
- 业务目标来源；
- 信息结构来源。

默认不作为：

- 最终视觉素材；
- 最终插画方向；
- 最终 SVG 元素来源；
- 最终背景；
- 最终配色方案；
- 最终视觉母题。

例如：

```text
需求原型里有“金库 + 金币”
≠
最终页面必须继续使用“金库 + 金币”
```

正确流程：

```text
原型 KV
↓
抽取主题 / 文案 / 核心利益点
↓
隔离旧视觉资产
↓
重新建立 Visual Concept
↓
重新设计 Hero / KV
```

---

# Theme → Color → Asset Routing｜主题 → 配色 → 资产路由

必须先理解业务主题，再决定颜色和视觉资产。

禁止：

```text
先套品牌蓝
↓
再找一个通用 SVG / 插画填进去
```

正确顺序：

```text
业务主题
↓
页面目标
↓
核心视觉隐喻
↓
主色 / 辅色 / 点缀色
↓
Hero Visual / SVG / Illustration
↓
整页背景与卡片系统
```

---

## 主题路由示例

### 充值 / 活动
优先语义：

- 时间
- 截止点
- 收益连续性
- 权益
- 到账
- 节日氛围

可用视觉：

- 日历
- 时间装置
- 收益点
- 节奏 / 路径
- 权益 / 券

不应默认复用：

- 金库
- 金币
- 红包
- 宝箱
- 通用礼盒

---

### 策略 / 产品
优先语义：

- 配置
- 平衡
- 核心-卫星
- 周期
- 风险控制
- 多资产关系

可用视觉：

- 配置结构
- 资产关系
- 节奏 / 周期
- 路径 / 平衡
- 抽象金融结构

不应默认复用：

- K 线
- 上涨大箭头
- 通用地球
- 通用玻璃球

---

### 保险
优先语义：

- 家庭
- 守护
- 安心
- 医疗服务
- 陪伴

可用视觉：

- 家庭人物
- 医疗服务
- 守护关系
- 保障场景

专项规则继续遵循：

`qieman-insurance-design`

---

### 内容 / 投教
优先语义：

- 阅读
- 解释
- 认知
- 关系
- 编辑感

可用视觉：

- 编辑型插画
- 信息结构
- 章节视觉
- 抽象知识关系

---

### VIP / 高净值
优先语义：

- 稀缺
- 专属
- 长期主义
- 配置
- 私享服务

专项规则继续遵循：

`qieman-vip-design`

- 连接

- 智能

可用视觉：

- 节点

- 能力容器

- 机器人头

# SVG / Illustration Theme Check｜视觉资产主题检查

Hero 中每一个 SVG / Illustration / 图形元素必须回答：

1. 它和当前主题是否直接相关？
2. 它是否帮助用户理解页面核心价值？
3. 它是否能建立整个页面的视觉基调？

若任一项为“否”，则：

> **不得作为 Hero 核心视觉。**

禁止使用：

- 无意义方块；
- 纯装饰圆球；
- 与主题无关的几何体；
- 原型遗留 SVG；
- 通用金融装置占位符；
- 只为“填满右侧”而存在的视觉元素。

---

# KV Determines Page Tone｜首屏决定整页基调

KV / Hero 完成后，整页必须继承其视觉语言：

- 背景色关系；
- Brand Blue 使用比例；
- 暖色比例；
- Card Surface；
- Icon / Illustration 风格；
- 光影；
- 圆角；
- 视觉密度。

禁止：

```text
Hero 一套视觉
正文另一套视觉
```

应当：

> **Hero 是整页视觉系统的起点。**

# KV Rebuild QA｜KV 重建验收

当任务为“视觉重做”时，交付前必须检查：

- [ ] Hero 是否重新建立 Visual Concept？
- [ ] 是否没有直接复用需求原型旧图 / 旧 SVG？
- [ ] 配色是否由主题推导，而不是机械套品牌蓝？
- [ ] Hero 主视觉是否与业务主题直接相关？
- [ ] SVG / Illustration 是否经过 Theme Check？
- [ ] 是否为 Title / KPI / CTA / Transition 留出安全区？
- [ ] Hero 是否能定义整页视觉基调？
- [ ] 正文是否继承 Hero 的视觉语言？
- [ ] 375px 下是否仍有清晰主体？
- [ ] 是否明显区别于需求原型视觉表现？

如果：

```text
业务结构没错
但 Hero 仍像原型换皮
```

则：

> **KV Visual Rebuild Failed**


# 3. Hero Layout Gate｜Hero 布局强制验收

Hero 是视觉错误最高发区域，必须单独验收。

必须检查以下对象是否冲突：

```text
Title
Subtitle / Body Copy
Hero Visual
KPI
CTA
Badge / Tag
Transition Safe Area
```

## 3.1 文字安全区

必须保证：

- 标题不被 KPI / 插画 / 装饰覆盖；
- 副标题不被视觉主体穿插；
- 多行文本有稳定宽度；
- 375px 宽下仍可正常阅读；
- 文字区与视觉区有明确权重关系。

禁止：

- KPI 压标题；
- 视觉主体穿过正文；
- 文案为了“留位置”被压成过窄列；
- 文字区域靠绝对定位硬塞。

---

## 3.2 KPI 安全区

Hero 内存在 KPI 时：

- KPI 必须拥有独立空间；
- KPI 不得锚定到错误容器；
- KPI 不得覆盖标题 / 文案；
- KPI 与 Hero 底部 Transition Zone 必须同时可用；
- 同级 KPI 必须等权；
- 375px 宽下不得溢出、截断、错位。

优先：

```text
Title / Copy
↓
KPI
↓
Transition
```

或：

```text
左文案 + 右视觉
↓
整行 KPI
↓
Transition
```

不建议：

```text
绝对定位 KPI
→ 压在标题 / 正文之上
```

---

## 3.3 Hero Visual 安全区

核心视觉主体必须：

- 不进入主标题安全区；
- 不占用 KPI 空间；
- 不压入 Transition Safe Area；
- 缩到移动端后仍然有明确识别；
- 不能只剩一个“空白几何块”。

如果视觉主体只是：

- 白色方块
- 圆球
- 通用圆环
- 无业务语义的玻璃块

则视为：

> **Visual Concept Insufficient**

必须重新建立与业务主题相关的视觉概念。

---

# 4. Whole-page Visual Consistency Gate｜整页视觉一致性

成熟页面不是每个模块各自“好看”，而是整页属于同一视觉系统。

必须统一：

- 页面底色
- Surface / Card 系统
- 一级标题体系
- 圆角等级
- 阴影强度
- Icon 风格
- 强调色
- 间距节奏
- Illustration / Diagram 语言
- 数据卡视觉语法

核心原则：

> **外层系统统一，模块内部表达多样。**

允许：

- 图表不同
- Diagram 不同
- 内容卡不同
- 插画不同
- 模块内部结构不同

但这些必须被统一的页面系统承接。

---

## 4.1 背景连续性

优先判断：

- Hero 与正文背景是否自然衔接；
- 是否存在硬切；
- 是否存在无意义的大圆角切面；
- 是否只是为了“有承接”而增加装饰。

原则：

> **背景连续优先于人为切割。**

如果 Hero 与正文已经可通过同色系渐变自然衔接，不强制使用大圆角 Surface。

---

## 4.2 Card System

同一页面的同级卡片必须保持：

- 圆角一致；
- 阴影强度一致；
- 内边距一致；
- 背景关系一致；
- 标题位置一致。

但：

> **卡片一致 ≠ 卡片内部内容模板一致。**

模块内部可以根据业务内容采用：

- 图表
- 对比
- 配置图
- Diagram
- Icon + 文案
- 人物 / 场景
- 流程
- 时间轴
- UI Preview

---

# 5. Mature Design Gate｜成熟设计门槛

最终输出不能只满足“功能正确”。

必须判断：

## 5.1 构图成熟度
- 主次明确；
- 视觉重心稳定；
- 主体比例合理；
- 留白有目的；
- 不像素材拼贴。

## 5.2 视觉概念
- 视觉主体与业务主题有真实语义关系；
- 不依赖通用金融套路；
- 不使用“随便一个抽象物体”占位。

## 5.3 空间层次
- 前景 / 主体 / 背景关系清楚；
- 不要求复杂，但要有层次；
- 视觉主体不能悬浮失真。

## 5.4 品牌感
- 看起来属于且慢 / 盈米；
- 不是任意金融 App 都能复用；
- 品牌蓝、浅蓝、暖色比例合理；
- 金融语义色与品牌色不混淆。

## 5.5 阅读节奏
- 长页有节奏；
- 强弱模块有差异；
- 不全页同一种白卡堆叠；
- 信息密度高时仍可扫读。

## 5.6 移动端
必须通过 375px Gate：

- 主体清楚；
- 标题不挤；
- KPI 不错位；
- 图表不溢出；
- 小元素不变成噪音。

---

# 6. Anti-AI Visual Gate｜反 AI 初稿检查

出现以下情况视为视觉成熟度不足：

- 蓝色渐变 + 玻璃球；
- 通用盾牌；
- 通用地球；
- 圆环 + 漂浮几何；
- 大箭头；
- 无意义卡片悬浮；
- 每个模块都套同一种卡；
- 只换颜色、不换构图；
- 主体像“AI 占位符”；
- 视觉概念与业务无关。

如果用户连续要求“再生成一组”，默认必须主动降低同质化。

至少改变：

- 核心视觉隐喻；
- 构图方向；
- 主体类型；
- 空间关系；

中的 2 项以上。

# 2.4 Hero Handoff & Transition Contract｜KV → 正文承接正式规范

Hero 与正文之间的过渡不是单独的渐变效果，而是一个完整的视觉关系：

```text
Hero 主题视觉
↓
Transition Zone｜承接层
↓
First Content Surface｜首张正文内容面
```

核心目标：

> **让正文像从 Hero 的视觉氛围中自然进入，而不是“上面一张图、下面另一套页面”。**

本 Skill 必须读取或接受上游 `transition_mode`，统一使用：

```text
overlay-card
soft-gradient
flat-spacing
```

禁止在新输出中继续使用：

```text
rounded-surface
rounded-transition
card-overlap-style
```

旧文件可以兼容映射，但不得作为新规范继续输出。

---

## A. Universal Continuity Rules｜通用连续性规则

无论使用哪种 `transition_mode`，都必须满足：

### 1. Background Continuity｜背景连续

- Hero 与正文必须有共同的背景关系；
- 不允许图片资产在 Hero 底部出现明显矩形边缘；
- 不允许“图片结束 → 突然切页面底色”；
- 如果 Hero 使用独立图片资产，图片应作为局部视觉主体层，而不是整块矩形贴图；
- 图片边缘可通过透明蒙版、柔光、渐隐、雾化或同色背景融合；
- Hero 基底色应延续到 Transition Zone，再收敛到正文页面底色。

判断：

> 如果用户能明显看出“这里是一张图片的边界”，则 **Background Continuity Failed**。

### 2. Transition Zone｜承接层

Transition Zone 是 Hero 与正文之间的缓冲区，不是空白区。

默认建议：

```text
常规移动端：36–56px
推荐起点：约 44px
```

这是视觉建议，不是所有业务的硬编码值。

Transition Zone 应：

- 上部继承 Hero 氛围；
- 下部收敛到正文底色；
- 越靠近正文，视觉复杂度越低；
- 不出现明显色带；
- 不形成大片无意义雾化；
- 不出现“为了过渡而过渡”的空白。

### 3. Text Protection｜文字保护

标题、副标题、KPI、标签不能进入低对比度 Transition Zone。

必须保证：

- 最后一行核心文案位于稳定背景上；
- 渐变变浅不能导致文字失去对比；
- 主视觉与过渡不得挤压文字安全区；
- 文字区域与图像复杂区域主动错位；
- 若背景逐渐变浅，文字必须在变浅前完成收口。

核心：

> **先保护信息可读性，再处理过渡效果。**

### 4. Asset Edge Blending｜视觉资产边缘融合

使用图片、3D、插画或复合资产时：

- 主体可跨越 Hero 内部空间；
- 但资产边缘不得硬切；
- 底部靠近正文时应降低对比、密度和锐度；
- 不能为了“融入”而把主体整体糊掉；
- 面部、核心道具、关键识别结构必须保持清楚。

### 5. First Surface Relationship｜首卡关系

若上游选择 `overlay-card`：

- 首张正文内容面应与 Transition Zone 发生轻度空间关系；
- 视觉建议的 overlap 范围通常为 **20–28px**；
- 推荐参考值约 **24px**；
- 该值由 `qieman-business-content-design` 最终实现和调整；
- 首卡不应深度压进 Hero；
- 首卡也不应与 Hero 之间形成明显空档；
- 首卡圆角、阴影、背景必须与全页 Card System 一致。

目标：

> **首卡从 Hero 氛围中自然进入，而不是浮在一片空白上。**

---

## B. `overlay-card`

适合：

- 营销活动；
- 策略介绍；
- 产品介绍；
- 需要第一核心卡快速进入正文的页面。

视觉资产要求：

- Hero 底部预留 `overlap-safe area`；
- 底部视觉复杂度逐步下降；
- 核心主体、人物面部、Logo、关键道具避开重叠区；
- 不在图片内部伪造正文白卡；
- 不把假卡片、假 CTA 画进 KV；
- 不通过深度负空间制造“悬浮首卡”。

推荐交付参数：

```text
transition_mode: overlay-card
transition_zone_height: 36–56px（建议约 44px）
first_surface_overlap: 20–28px（建议约 24px）
asset_blend: soft-mask / fade / atmosphere-blend
text_protection: required
```

注意：

这些是 **Visual Handoff Recommendation**，最终 HTML 数值由主 Skill 决定。

---

## C. `soft-gradient`

适合：

- 保险；
- 医疗；
- 家庭保障；
- 服务；
- 陪伴类页面；
- 需要更柔和人物承接的页面。

视觉资产要求：

- Hero 底部向浅蓝 / 暖白 / 极浅灰自然收敛；
- 不出现明显色带和硬边；
- 人物或主体可以向下自然融入；
- 面部、手部、关键主体不能被渐变吞没；
- 正文可轻承接，也可以不压卡；
- 不强制制造 overlay-card 效果。

推荐交付参数：

```text
transition_mode: soft-gradient
transition_zone_height: 44–72px
first_surface_overlap: optional / low
asset_blend: atmosphere-fade
text_protection: required
```

保险场景默认：

```text
qieman-insurance-design
→ transition_mode = soft-gradient
→ qieman-marketing-visual-design 生成兼容视觉
```

---

## D. `flat-spacing`

适合：

- 投教；
- 报告；
- 内容专题；
- 编辑型页面；
- 信息优先、视觉不需要强承接的页面。

要求：

- Hero 在自身区域内完整收口；
- 底部干净；
- 不强行渐变；
- 不强行压卡；
- 不制造圆角切口来假装高级；
- 正文通过稳定 spacing 进入。

推荐交付参数：

```text
transition_mode: flat-spacing
transition_zone_height: minimal / none
first_surface_overlap: 0
asset_blend: contained
```

---

## E. Transition Regression Guard｜承接回归保护

当用户只反馈：

- 图片挤压文字；
- 过渡不自然；
- 图片裁切明显；
- 首卡衔接突兀；
- 某一处背景关系不对；

默认只修对应问题。

禁止为了局部承接问题：

- 重建已经正确的 Hero 构图；
- 改变已经确认的标题比例；
- 更换已确认的视觉母题；
- 改变正文模块结构；
- 重做卡片系统；
- 改变页面业务顺序；
- 添加新的视觉元素补洞。

原则：

> **局部问题局部修复，已验证正确的视觉关系进入 Regression Lock。**

若修复一个问题导致两个已经正确的部分回归：

> **Transition Regression Failed**

---

## F. Transition Ownership｜职责归属

`qieman-marketing-visual-design` 负责输出：

- Hero 底部视觉兼容；
- Transition Zone 视觉方向；
- overlap-safe area；
- Text Safe Area；
- Asset Blend Mode；
- 首卡承接建议值；
- 主视觉避让策略；
- Background Continuity 检查。

`qieman-business-content-design` 负责最终实现：

- 正文 `margin-top`；
- 首卡 `translate / margin`；
- 页面 DOM；
- Card Surface；
- Transition Zone 实际高度；
- Sticky CTA；
- 响应式适配；
- 最终 HTML。

推荐接口：

```text
transition_mode
transition_zone_height
first_surface_overlap
text_safe_area
visual_safe_area
asset_blend_mode
background_handoff_color
regression_lock
```

核心：

> **本 Skill 定义成熟的视觉承接标准；主 Skill 负责把标准正确实现成页面。**

# 4. 默认输出原则

默认优先输出：

1. **无字 KV**
2. **无字 Hero 背景图**
3. **透明底前景插画**
4. **可直接嵌入页面的主视觉资产**

默认不直接把标题、按钮、营销文案画进图片。

原因：

- 页面文字由 HTML / UI 层控制；
- 避免字体变形与文字错误；
- 保持页面可编辑；
- 便于多端适配。

> 核心原则：**文字留给页面，图片负责视觉。**

# 4.1 Hero / KV CTA 边界

本 Skill 不得因为“增强转化”自行创建业务 CTA。

规则：

- Requirement Source 没有 Hero CTA → 不新增。
- Requirement Source 明确有 Hero CTA → 只为按钮预留安全区，按钮仍由 HTML / UI 层实现。
- 用户明确要求 Hero CTA → 可以为其预留版式位置，但默认不把按钮文字直接画进图片。
- 产品卡 / 报价卡 / 权益卡中的 In-flow CTA 不归本 Skill 管理。
- Sticky CTA 不归本 Skill 管理。

> **视觉资产可以为 CTA 让位，但不能替业务决定 CTA。**

# 5. 适用场景


# 5.0 Business Source × Page Goal Router｜业务来源 × 页面目标双路由

`qieman-marketing-visual-design` 是且慢/盈米的**跨业务营销与内容视觉层**。


## 5.0.3 双路由示例

同一个“新增策略”，不同团队可以得到不同视觉方向：

```text

→ 营销转化
→ 更强主题识别 + 更聚焦利益点 + 更明确 KV

顾问团队 + 同一策略
→ 策略解释 / 产品解释
→ 更专业、更重机制和配置逻辑

内容团队 + 同一策略
→ 投教阅读
→ 编辑感、更克制、更强调认知表达

VIP 团队 + 同一策略
→ 产品解释 / 私享传播
→ 更高净值语境、更稀缺、更克制
```

再例如：

```text
内容团队 + 红利专题

→ 营销转化

顾问团队 + 红利策略介绍
→ 策略解释
```

- 复杂地图

可考虑：

- 跨区域连接
- 空间层级
- 全球视野
- 海内外元素的简化对应

避免：

- 巨型地球
- 地球仪
- 世界地图占据主体

---

## 14.4 红利 / 现金流

可考虑：

- 周期性流动
- 稳定输出
- 连续节点
- 时间序列
- 持续供给

避免：

- 金币雨
- 金元宝
- 大量现金
- 财神符号

---

## 14.5 活动 / 充值 / 权益

可考虑：

- 时间
- 日历
- 路径
- 节奏
- 轻量礼遇
- 可用权益
- 资金待机 / 收益继续

避免：

- 电商促销爆炸贴
- 夸张优惠券堆叠
- 巨型价格数字

---

## 14.6 保险 / 医疗

可考虑：

- 透明盾牌
- 医疗服务
- 家庭关系
- 医疗路径
- 保障层
- 安心空间

避免：

- 病弱人物
- 医院恐惧场景
- 过度医疗器械堆叠

# 15. AI 生图反同质化规则

金融生图最容易出现重复母题。

以下元素默认降低优先级：

- 道路
- 山峰
- 上涨箭头
- 城市
- 金币
- K 线
- 交易屏
- 柱状图
- 地球
- 圆环
- 放大镜
- 钻石
- 巨型玻璃装置

同一项目连续生成时：

> 不得连续两轮使用相同视觉母题。

# 16. 强禁用元素

默认禁止：

- 城市天际线
- 门
- 椅子
- 沙发
- 会议室
- 多人会议
- 会所空间
- K线
- 交易屏
- 大量金币
- 金元宝

- 复杂桌面静物
- 过度玻璃装置

如用户明确要求某元素，可例外。

---

# 17. 简洁度规则

用户说“简洁”时，必须理解为：

- 第一视觉中心明确；
- 辅助信息主动降权；
- 保留有效留白；
- 控制视觉噪音；
- 不用复杂背景填满；
- 不用重复装饰；
- 不通过堆元素制造完成度。

“简洁”不是固定元素数量。

判断标准：

> 删除某元素后，如果主题更清楚、比例更稳定、信息不受损，则应该删除。

> **简洁 ≠ 什么都没有。**  
> **简洁 = 每一个留下来的元素都有必要。**


---


# 17.1 Visual Quality System｜视觉成熟度

本节用于解决“语义正确，但画面仍像普通 AI 素材”的问题。

目标不是增加复杂度，而是提高：

- 构图成熟度
- 主题识别度
- 空间层次
- 光影一致性
- 品牌辨识度
- 移动端识别度

> **高级感优先来自比例、留白、层次、光影与材质一致性，而不是来自元素数量。**

---

## 17.1.1 Composition Maturity｜构图成熟度

成熟构图默认满足：

```text
明确第一视觉中心
+
稳定的文字安全区
+
必要的辅助关系
+
低噪音背景
```

不规定固定主体或辅助元素数量。

核心视觉关系必须：

- 第一眼可识别；
- 尺度与 Hero 比例合理；
- 与业务主题直接相关；
- 辅助元素不抢焦点；
- 不压入文字安全区；
- 不压入 `overlap-safe area` / `soft-gradient` 底部承接区；
- 在 375px 下仍有清晰层级。

避免：

- 多个同权重主体；
- 为填空加入漂浮装饰；
- 主体过大挤压文案；
- 主体过小变成无意义图标；
- 复杂度来自数量，而不是构图和细节。


## 17.1.2 Spatial Depth｜空间层次

非纯扁平信息图场景，优先建立轻量三级关系：

```text
前景：少量、低权重，可承担轻遮挡
中景：核心视觉主体
背景：低对比氛围 / 光影 / 几何 / 空间
```

规则：

- 层次必须服务主体，不得制造复杂场景；
- 前景不遮挡人物脸部、关键产品或业务符号；
- 背景不出现高对比杂物；
- 轻 3D 可使用空气透视、柔焦和软阴影建立空间感；
- 扁平矢量不强制三级空间，但仍要有前后层级和视觉节奏。

---

## 17.1.3 Lighting & Material｜光影与材质一致性

同一画面默认只允许一个主要光源逻辑。

必须保持：

- 高光方向一致；
- 阴影方向一致；
- 物体落地关系合理；
- 透明 / 半透明材质折射逻辑一致；
- 同类元素材质一致；
- 透视方向一致。

避免：

- 每个元素各自发光；
- 左右同时出现冲突光源；
- 塑料玩具感过强；
- 玻璃、金属、磨砂材质混用且无逻辑；
- 软阴影和硬阴影随机混用；
- 3D 物体悬空无接触关系。

---

## 17.1.4 Brand Color Discipline｜品牌色控制

默认：

- 品牌蓝承担主要视觉面积；
- 浅蓝承担空间层次；
- 白色承担呼吸感；
- 暖橙 / 暖珊瑚 / 暖黄承担关键视觉焦点；
- 暖色默认不超过约 20%。

保险、医疗场景：

- 蓝白为主；
- 暖色只用于人物肤色、关键利益点、局部服务语义；
- 不允许整屏橙色或粉色营销化。

金融场景：

- 不使用大面积绿色；
- 红 / 绿只在明确金融数据语义中使用，不作为 Hero 主色关系。

---

## 17.1.5 Semantic Differentiation｜业务语义差异化

不同业务类型不得长期复用同一套视觉母题。

业务场景以 `5.0 Business Source × Page Goal Router` 双路由为主；保险只是其中一个较轻的垂类，不得成为默认模板。

### 策略 / 投资

优先：
- 结构
- 配置
- 平衡
- 周期
- 时间
- 多资产关系

### 保险 / 医疗

优先：
- 家庭
- 医疗服务
- 保障关系
- 陪伴
- 专业服务
- 就医路径

### 营销活动

优先：
- 时间
- 权益
- 轻礼遇
- 节奏
- 领取 / 到账 / 触发关系

### 内容 / 报告

优先：
- 编辑感
- 信息结构
- 克制的抽象视觉
- 品牌氛围

禁止把所有场景都做成：

```text
蓝色渐变
+ 玻璃卡片
+ 圆环
+ 漂浮几何
+ 通用盾牌
```

---

## 17.1.6 Mobile Readability Gate｜移动端识别度

Hero / KV 最终必须经过 **375px 宽视觉检查**。

缩小到移动端后仍应满足：

- 核心主体一眼可识别；
- 主题仍然成立；
- 文字安全区没有被侵入；
- 关键人物 / 道具没有被裁断；
- 辅助元素不会缩成噪点；
- 不依赖细小纹理表达主题。

若缩小后主体不清楚：

> 优先删减辅助元素、放大主体、增加留白，而不是增加锐化或更多细节。

---

## 17.1.7 Premium Simplicity｜高级简洁

“高级”不等于：

- 更多玻璃
- 更多渐变
- 更多粒子
- 更多装饰
- 更深阴影
- 更复杂 3D

优先顺序：

```text
主题准确
>
主体比例
>
留白
>
层次
>
光影
>
材质
>
装饰
```

若前五项已经成立，装饰可以为 0。

---

# 17.2 Anti-Homogeneity Upgrade｜去同质化升级

同一业务线或同一项目连续生成时：

- 同一视觉母题最多连续使用 1–2 次；
- 下一轮必须主动改变至少一项：
  - 核心视觉母题
  - 构图方向
  - 主体类型
  - 空间关系
  - 视觉隐喻
- 仅换色不算新方案；
- 仅更换小装饰不算新方案；
- 同一种“蓝色玻璃 3D 装置”不得反复作为万能答案。

当用户要求“再生成一组”时，默认理解为：

> **在保持品牌与业务语义一致的前提下，主动降低与上一组的视觉同质化。**

---

# 17.3 Visual Quality Gate｜交付门槛

交付前必须检查以下 7 项：

1. **主体尺度**：核心主体是否足够大、足够明确？
2. **主题识别**：不看标题，是否仍能感受到业务主题？
3. **文字安全区**：标题 / 副标题区域是否干净？
4. **噪音控制**：是否存在 3 个以上无意义装饰或漂浮物？
5. **移动端**：缩到 375px 后是否仍然清晰？
6. **反同质化**：是否与上一版 / 上一组明显重复？
7. **一致性**：光影、透视、材质是否统一？

其中以下为硬性失败条件：

- 主题识别弱；
- 文字安全区被占；
- 移动端主体不可识别；
- 主体透视 / 人物结构明显错误；
- 与用户已否定或近期重复母题高度相似。

出现硬性失败：

> **不得直接交付，应先简化或重新生成。**

---


# 18. 背景图规则

背景图默认：

- 无文字
- 无按钮
- 无 Logo
- 不把整个页面画进去
- 不出现 UI 卡片
- 不生成完整 H5 截图
- 不生成假的数据模块
- 不生成假的正文白卡 / 首卡
- 不把 Sticky CTA / 产品卡 CTA 画进视觉资产

它只负责：

> Hero / KV 视觉背景。

---

# 19. 透明前景插画规则

当页面需要更强可控性时，优先生成：

> 透明底前景插画

而不是整张背景。

优点：

- HTML 可控制位置
- 可调大小
- 可适配多尺寸
- 可替换背景色
- 减少生成模型对版式的破坏

推荐结构：

```text
HTML / CSS 背景
+
透明 PNG 前景插画
+
HTML 标题文字
```

---

# 20. KV 视觉复杂度

推荐：

```text
70% 可控页面
30% AI 视觉资产
```

不要：

```text
100% AI 生成整页
```

AI 负责：

- 视觉主体
- 插画
- 背景
- 氛围

HTML / UI 负责：

- 文字
- 按钮
- 数据
- 卡片
- 排版

---

# 21. 主题准确度 Gate

生成前必须回答：

1. 这张图的业务主题是什么？
2. 用户第一眼能不能感受到主题？
3. 是否有明确金融 / 保险 / 活动语境？
4. 是否只是“漂亮但不相关”？
5. 视觉元素是否在服务文案？

如果主题识别弱：

> 不得仅靠标题解释图片。

---

# 22. 留白 Gate

必须检查：

- 标题区域是否安全
- 主体是否遮挡文案
- 视觉重点是否和文字抢焦点
- 移动端裁切后是否还能保持主体完整
- 画面边缘是否有高权重元素被裁断

---

# 23. 清晰度 Gate

必须保证：

- 主体清晰
- 边缘干净
- 透视正确
- 不变形
- 不出现多余手指 / 多余肢体
- 不出现错误几何结构
- 图标不糊
- 不使用水印
- 不出现乱码文字

---

# 24. 品牌一致性 Gate

检查：

- 蓝色是否接近且慢品牌体系
- 暖色是否控制
- 是否过饱和
- 是否过黑
- 是否过度奢华
- 是否低幼
- 是否像泛 AI 金融素材
- 是否具备且慢的宁静、可信赖与克制感

---

# 25. 视觉层级 Gate

一个 KV 只允许：

- 1 个一级视觉主体
- 1~2 个二级辅助视觉
- 少量背景层

不允许：

> 每个元素都在抢视觉中心。

---

# 26. 多方案生成规则

用户要求“多方案”时：

不要只变颜色。

每张应至少改变其中 2 项：

- 核心视觉母题
- 构图
- 主体元素
- 空间关系
- 视觉隐喻
- 风格强度

例如 4 张方案：

```text
A：时间隐喻
B：结构隐喻
C：场景隐喻
D：抽象金融隐喻
```

---

# 27. 参考图使用规则

参考图只用于提取：

- 风格
- 材质
- 构图
- 配色
- 光影
- 精致度

不得机械复制：

- 原图主体
- 原图业务符号
- 原图文字
- 原图品牌内容

如果用户说：

> “参考风格，不要改变构图”

则：

- 构图锁定
- 视觉风格转换
- 内容元素按用户要求替换

---

# 28. 已确认资产优先级

如果用户已经确认：

- 某人物
- 某 IP
- 某插画
- 某视觉主体

后续应：

> 基于已确认资产继续变体。

不得每轮重新生成完全不同的人物或主视觉。

---

# 29. IP 规则

如使用且慢 IP：

- 不改变人物比例
- 不改变核心识别
- 不随意更换服装与面部特征
- 动作变化可以
- 场景可以变化
- 输出时保持高清

涉及小顾等 IP 时，优先使用对应 IP Skill。

---

# 30. 金融表达规则

营销视觉可以有金融语义，但应克制。

推荐：

- 资产配置
- 时间
- 周期
- 分散
- 稳定
- 长期
- 收益连续性
- 组合结构

不推荐：

- 投机
- 暴涨
- 赌徒式收益
- 满屏红绿
- K线交易
- 财富炫耀

---

# 31. 保险表达规则

保险视觉的目标是：

> 专业、安心、可靠、有人协助。

推荐：

- 蓝白
- 少量暖橙
- 轻 3D
- 柔光
- 医疗符号
- 家庭守护
- 服务路径

避免：

- 病患痛苦
- 重症恐惧
- 医疗恐吓
- 全蓝医疗器械堆叠

---

# 32. 营销文案与视觉关系

视觉必须回应：

- 标题主题
- 核心利益点
- 用户场景

例如：

```text
标题：好时光，小收益
视觉：
时间 + 连续收益节点
```

而不是：

```text
标题：好时光，小收益
视觉：
随机金币 + 城市 + 上涨箭头
```

---

# 33. Hero 不得“替页面做 UI”

禁止在生图里出现：

- 卡片
- 按钮
- 表格
- 图表
- 导航
- 底部 CTA
- 手机 UI
- H5 页面截图

除非用户明确要求制作 UI Mockup。

---

# 34. 输出形式

默认：

- PNG
- 高清
- 无字

需要时：

- 透明 PNG
- 纯白背景
- 指定背景色
- 多尺寸适配

---

# 35. 推荐输出数量

默认：

- 单次 4 张方案

若用户指定：

- 1 张
- 2 张
- 3 张
- 4 张

则严格按数量执行。

---

# 36. 页面视觉增强模式

当用户提供完整页面 HTML / 截图，并说：

> “页面不动，只优化 KV”

则执行：

```text
锁定页面结构
锁定文案
锁定卡片
锁定图表
锁定 CTA
↓
只提取 Hero 视觉区域
↓
分析主题
↓
生成 KV 资产
```

不得重新生成页面。

---

# 37. 页面联动模式

当新 KV 生成后，如果用户要求替换进 HTML：

允许调整：

- Hero background-image
- 前景图尺寸
- 前景图位置
- Hero 最小高度
- 标题安全区

不允许调整：

- 下方模块结构
- 数据
- 卡片
- 图表
- CTA
- 文案

---

# 38. 版本稳定性

用户确认某 KV：

> “这个方向可以”

则该版本成为：

`Locked Visual Direction`

后续修改：

- 只改用户指出部分
- 不随机切换母题
- 不重做全部构图
- 不改变已确认风格

---

# 39. Visual Regression Gate

每轮修改后检查：

- 主视觉是否仍为同一方向
- 色调是否漂移
- 主体是否变形
- 留白是否丢失
- 是否新增无关元素
- 是否重新出现禁用元素
- 是否改变用户确认的比例与构图

---

# 40. Prompt 生成模板

内部图像提示词必须包含：


# 41. 标准调用话术｜营销活动 KV

```text
调用 qieman-marketing-visual-design，
根据页面主题生成营销活动 KV。

主题：
【填写】

要求：
- 页面内容结构保持不变，只优化 Hero / KV 视觉
- 生成无字背景图
- 且慢品牌蓝体系
- 简洁、专业、可信赖，有适度营销感
- 保留标题安全区
```

# 42.1 Visual Handoff Checklist｜视觉交付检查

生成 Hero / KV / 背景资产前检查：

- [ ] 是否明确页面 `transition_mode`？
- [ ] 是否使用 `overlay-card / soft-gradient / flat-spacing` 新命名？
- [ ] Hero 与正文背景是否连续，而不是硬切？
- [ ] 图片资产是否没有明显矩形裁切边缘？
- [ ] 是否为 overlay-card 预留 overlap-safe area？
- [ ] Transition Zone 是否足够自然、不过长、不过空？
- [ ] soft-gradient 是否在底部自然收敛，而不是硬切？
- [ ] flat-spacing 是否避免强行做渐变 / 圆角切口？
- [ ] 是否没有在图片内部伪造正文卡片？
- [ ] 是否没有擅自增加 Hero CTA？
- [ ] 是否没有把 Sticky CTA / 产品卡 CTA 画进图片？
- [ ] 是否保留标题 / 副标题文字安全区？
- [ ] 核心文案是否完全避开低对比度过渡区？
- [ ] 第一视觉中心是否明确？
- [ ] 辅助元素是否全部必要，而不是为了填空？
- [ ] 删除冗余元素后是否更清晰？
- [ ] 核心主体是否避开正文重叠区？
- [ ] 如果是保险页面，是否遵循 `qieman-insurance-design`？
- [ ] 是否只交付视觉资产 / 视觉方向，不改正文业务结构？
- [ ] 核心主体缩到 375px 后是否仍可识别？
- [ ] 光源、阴影、透视和材质是否统一？
- [ ] 是否避免无意义漂浮装饰和素材拼贴？
- [ ] 是否与上一轮视觉母题明显区分，而不是只换颜色？
- [ ] 高级感是否主要来自比例、留白、层次、光影和细节完成度？
- [ ] 局部优化是否没有破坏已经确认正确的 Hero / Transition / Card 关系？

若背景衔接、文字保护、资产融合或首卡关系出现明显断层：

> **Visual Handoff Failed**

# 45. 固定原则总结

本 Skill 的核心不是：

> “生成一张好看的图”

而是：

> **生成一张能真正进入且慢业务页面、可被 HTML 使用、主题准确、构图可控、品牌一致的营销视觉资产。**

```text
>

>

>
品牌一致性
>
视觉精致度
>
装饰感
```

# 46. 最终硬规则

1. 页面结构默认不改。
2. 页面文案默认不改。
3. KV 默认无字。
4. 不生成完整页面截图。
5. 不让 AI 同时决定页面结构和视觉。
6. 先定视觉母题，再生图。
7. 一张图只保留一个主视觉中心。
8. 默认保留明确文字安全区。
9. 禁止泛金融 AI 套路化元素重复使用。
10. 已确认视觉方向不得随机重构。
11. 视觉增强不能破坏 `qieman-business-content-design` 已稳定的页面布局。
12. 需要数据图表时交给 `qieman-chart-design`，本 Skill 不负责图表设计。
13. 需要页面基础组件时遵循 `qieman-ui-design`。
14. 需要垂类人物 / IP / 保险定制资产时按需叠加对应 Skill。


> 默认不得直接沿用需求原型中的旧视觉资产。
